# OmniFlow App 显示与可读性基线

更新时间：2026-07-31
适用范围：`omniflow-app` 前端页面、工作区、内置浏览器、目录树、弹框、工具页和后续新页面的显示尺寸、字号、密度与可读性校准。

## 1. 概述

当前项目里已经出现过两类相反但相关的问题：

- 页面在主开发显示器上看起来偏小
- 早期开发长期依赖 Chromium 页面缩放，导致恢复 `Cmd/Ctrl+0` 后界面整体偏大
- 不同页面的字号、行高、按钮密度不一致
- 同样是“工具栏”“列表”“说明文案”，不同页面给出的视觉重量差异过大
- 暗色和亮色主题下，有些文字和按钮虽然“能看见”，但不够舒服和明确

这份文档的目标不是立刻把全项目一夜之间统一，而是先固定一套可讨论、可观察、可逐步落地的基线：

1. 先明确哪些显示参数必须统一
2. 先给出一版候选档位
3. 先定义一张“观察样张页”该展示什么
4. 后续页面改造时，优先往这套基线靠，而不是继续每页自由发挥

## 2. 当前结论

### 2.1 这不是“纯字体”问题

“页面看起来小”通常不是单独某个 `font-size` 引起的，而是几件事叠在一起：

- 正文偏小
- 行高太紧
- 图标小，但点击热区也小
- 工具栏高度不够
- 列表行高不够，导致内容显得挤
- 面板 padding 太小，视觉呼吸感不足
- 次级文本和禁用态太灰，视觉上像缩进去了一层

所以后续不能只盯着字号，而要把“字号 + 行高 + 间距 + 控件高度 + 对比度”当成一组来定。

### 2.2 当前默认假设

2026-05-03 起，显示基线进入“恢复 `100%` 页面缩放”的迁移阶段：

- 主要观察场景：桌面端主工作区
- 视觉参照为：先按 `Cmd/Ctrl+0` 恢复默认页面缩放，再按 4 次 `Cmd/Ctrl-` 后得到的历史舒适尺寸
- 这组舒适尺寸约等于 Chromium `67%` 页面缩放下的观感
- 后续应通过真实 CSS 尺寸迁移，让 `100%` 页面缩放尽量接近上述观感
- 应用级 `Cmd/Ctrl +/-/0` 页面缩放已禁用，不再作为 UI 尺寸比对手段；内置浏览器网页自身缩放暂不纳入这条限制
- 已确认的参照样张是 `src/views/settings/index.tsx` 设置页；主工作区按同一密度继续收敛
- 旧的“新页面文本不得低于 `16px`”不再作为迁移期硬约束；工作区高频控件可使用 `10px ~ 13px` 文案，但必须保证行高、截断、点击热区和主题对比度可用
- 目录树右键菜单可在通用 `directory-context-menu` 基础上叠加更紧凑样式，但必须沿用同一套颜色、圆角、hover 和图标槽语义，只压缩宽度、行高、padding 与图标尺寸
- 目录树右键触发的弹框 / overlay（新建文件、上传确认、删除确认、属性、重命名输入）必须使用紧凑工作区基线：标题约 `14px`、正文约 `12px`、按钮高约 `28px`、输入框高约 `24px ~ 28px`，不能回到旧缩放时代的 `16px ~ 18px` 正文和 `40px` 按钮
- 顶部滑入反馈（Semi Toast / Notification）按历史舒适尺寸收敛到约 `67%`：Toast 约 `10px / 14px`、`8px` 上下 padding、最大宽度约 `348px`；Notification 标题约 `11px`、正文约 `10px`。这类全局反馈只在 `src/assets/css/feedback.less` 统一调整，业务调用点不单独写尺寸

## 3. 第一版候选字号层级

下面不是最终定稿，而是建议先做成观察样张的候选档位。

### 3.1 字号梯度

| 层级 | 建议字号 | 主要用途 | 当前建议 |
| --- | --- | --- | --- |
| XS | `13px` | 极轻量辅助信息、时间戳、极短标签 | 慎用，不做正文 |
| S | `14px` | 次级说明、meta、弱提示、表格次文本 | 可用，但不做主要交互正文 |
| M | `15px` | 目录树、tab、输入框、按钮文案、常规列表正文 | 推荐作为桌面高频默认值 |
| L | `16px` | 正文段落、表单说明、普通面板正文 | 推荐作为宽松正文值 |
| XL | `18px` | 次级标题、关键值、工具区重点说明 | 推荐作为强调层 |
| 2XL | `20px` | 小区块标题、重要操作区标题 | 推荐作为模块标题层 |
| 3XL | `24px` | 页面标题、空状态标题 | 推荐作为页面级标题起点 |
| 4XL | `28px` | 强页面标题、欢迎区标题 | 仅少数页面使用 |

### 3.2 暂时不建议的做法

- 大面积正文继续使用 `12px` 或 `13px`
- 主要按钮文案用 `13px`
- tab 文案、目录树文案、URL 栏文案低于 `15px`
- 通过把文字缩小来“塞更多信息”
- 暗色模式里依赖更灰的文字来制造层级

## 4. 第一版候选行高与控件高度

### 4.1 行高

| 内容类型 | 建议值 |
| --- | --- |
| 紧凑标签 / 单行按钮 | `1.2 ~ 1.3` |
| 常规正文 / 列表项 | `1.45 ~ 1.6` |
| 标题 | `1.2 ~ 1.35` |
| 多行说明文本 | `1.6 ~ 1.75` |

### 4.2 常见控件高度候选

| 控件 | 候选值 | 备注 |
| --- | --- | --- |
| 顶部工具栏按钮热区 | `32px ~ 36px` | 图标可以小，热区不能太小 |
| 输入框高度 | `36px ~ 40px` | URL 栏、搜索框、普通输入尽量统一 |
| 列表 / 树节点行高 | `34px ~ 40px` | 目录树和右键菜单不能过瘦 |
| 表格常规行高 | `40px ~ 44px` | 避免整页显得发虚且难点 |
| 面板标题区高度 | `44px ~ 52px` | 区块分隔更稳定 |

## 5. 观察样张页应该包含什么

为了让你在自己的显示器上直接判断“哪组更舒服”，建议做一张专门的 UI 校准页。第一页不追求复杂逻辑，只追求对比清楚。

建议样张页至少包含下面几块：

### 5.1 浏览器头部样张

- 标签栏文案：`14 / 15 / 16`
- URL 输入文案：`14 / 15 / 16`
- 工具栏图标：`16 / 18 / 20`
- 头部按钮热区：`32 / 34 / 36`

观察点：

- 哪一档在你当前显示器上最像“正常浏览器”
- 哪一档最不容易显得发虚、细碎

### 5.2 目录树样张

- 节点文案：`14 / 15 / 16`
- 次级计数或路径：`13 / 14 / 15`
- 节点行高：`34 / 36 / 38 / 40`
- 右键菜单宽度、菜单项上下 padding、图标尺寸

观察点：

- 哪组最容易连续扫读
- 哪组在不打开全部节点时仍不显拥挤

### 5.3 列表 / 卡片样张

- 列表标题：`16 / 18`
- 主信息：`15 / 16`
- 次信息：`14 / 15`
- 按钮文案：`14 / 15 / 16`
- 卡片内边距：`16 / 20 / 24`

观察点：

- 哪组既清楚又不脏
- 哪组更适合当前项目这种工具型桌面 UI

### 5.4 弹框 / 表单样张

- 弹框标题：`18 / 20 / 22`
- 正文：`15 / 16`
- help text：`14 / 15`
- 输入框高度：`36 / 40`
- 主按钮与次按钮对比度

观察点：

- 白天和夜间模式下，是否都足够明确
- 能否一眼看清主操作而不靠 hover 才知道能点

### 5.5 空状态 / 欢迎页样张

- 页面标题：`24 / 28`
- 描述文本：`15 / 16 / 18`
- CTA 按钮：`15 / 16`

观察点：

- 是否显得轻松、清爽，而不是又大又空或者又小又弱

## 6. 前端开发需要先定下来的项目

下面这些建议后续全部收成统一标准，不要再分散在各页面里临场决定。

### 6.1 排版层级

- 页面标题字号
- 区块标题字号
- 正文字号
- 次文本字号
- 标签 / meta 字号
- 按钮文案字号
- 输入框文字字号
- tab 文字字号

### 6.2 密度与尺寸

- 头部栏高度
- 工具栏按钮热区
- URL 栏高度
- 目录树节点行高
- 右键菜单项高度
- 列表 / 表格行高
- 弹框按钮区高度
- 常用面板 padding

### 6.3 宽度与最小尺寸

- 目录树最小宽度
- 工具面板最小宽度
- 浏览器设置页内容区最小宽度
- 弹框最小宽度
- 表单标签列宽建议
- 操作按钮最小宽度

### 6.4 图标与点击热区

- 常规图标显示尺寸
- 常规图标按钮热区
- 顶栏图标尺寸
- 列表行内图标尺寸
- 空状态插画 / 大图标尺寸

#### 6.4.1 目录树图标槽位

目录树节点图标必须先统一“槽位”，再按图标自身形态做极小视觉校准：

- 目录树**文件 / 默认目录 / 内置类型 / 归档类型**四类图标统一放进 `15px * 15px` 槽位，全部走 `<img>` from custom material SVG 这一条渲染路径，不再分流到 Semi 内置 `IconFolder`。
- 图标尺寸的单一来源是 `src/features/file-explorer/utils/file-node-icon.tsx` 顶部的 `TREE_ICON_SIZE = 15` 常量；CSS 的 `15px` 字面量必须与之一致，禁止再出现"img 写 20、CSS 写 15"这类双源声明。
- 图标元素必须使用 `object-fit: contain`，不得只依赖 SVG 自身 `viewBox` 或 `width/height` 来决定最终视觉大小。
- 内置类型图标的视觉面积参考默认文件夹（`folder-base.svg`）：主体图形不应明显高过同一行的默认文件夹图标，也不应比普通文件夹小一圈。
- **所有目录类图标都必须提供闭合与展开两态**，例如 `folder-base.svg` / `folder-base-open.svg`、`folder-video.svg` / `folder-video-open.svg`；目录树渲染时按节点展开状态切换（参见 `directory-tree/index.tsx` 的 `patchNodes` 逻辑），不允许只用单个静态图标。
- 不同 SVG 的有效图形面积不一致时，只允许在类型 class 上用 `0.5px ~ 1.5px` 的 `padding` 做感知大小校准，例如 `comic-folder`、`asmr-folder`、`audio-folder`、`video-folder`、`gallery-folder`、`default-folder`。本仓库当前所有目录类图标共享 0.5px 基准。
- 新增目录树语义图标时，必须同时检查默认目录、漫画归档、ASMR 归档、音频归档和视频归档同屏展示效果，避免出现某个图标因为 SVG 内容铺满画布而明显偏大。

### 6.5 明暗主题可见性

- 主文本对比度
- 次文本对比度
- 禁用态的“还能看见但明确不可点”的表现
- 激活态是不是靠背景、边框、文字色还是三者组合
- 白天主题是否“发灰发脏”
- 夜间主题是否“发糊发闷”

### 6.6 截断与折行

- tab 文案的省略策略
- 目录树过长名称的省略策略
- URL、路径、资源名称的展示优先级
- 表格列是否允许换行
- 描述文本在什么情况下必须折行而不是缩小字号

### 6.7 文件预览 tab 宽度与动效

- 文件预览 tab 不再按内容撑宽，默认宽度为 `168px`，最小宽度为 `96px`。
- 当可用宽度不足时，tab 应先整体等比例压缩到最小宽度；最小宽度仍放不下时，再使用已有横向滚动条。
- 拖拽重排 tab 时使用上一帧位置做布局过渡；关闭 tab 时先触发真正关闭，再由 tab bar 保留本地退出快照折叠宽度，让相邻 tab 通过 flex 布局自然收回，避免关闭瞬间出现旧位置残影，同时不延迟媒体释放链路。
- tab 前缀图标复用目录树图标解析，不额外添加彩色胶囊或文字标签。

### 6.8 工作区滚动条

- 高频工作区的普通滚动容器默认使用窄滚动条，WebKit / Electron 下横纵尺寸优先取 `8px`；轨道保持透明，避免在暗色内容区出现突兀的亮色边带。
- 滑块颜色必须复用 `--app-scrollbar-thumb`、`--app-scrollbar-thumb-hover` 和 `--app-scrollbar-track` 主题 token，不在业务组件中写死明暗色值。
- 滚动条右下角交汇区应与轨道同为透明，横纵滚动条同时出现时不能产生白色方块。
- 不设置全局 `*::-webkit-scrollbar` 规则。PDF、漫画、图集、编辑器等滚动模型不同，应由实际滚动容器局部应用；当多个同类容器的显隐和交互规则稳定一致后，再抽 styled-components 共享片段。

## 7. 新页面临时准入标准

这套标准当前只约束**后续新页面和新模块**，不要求为了对齐它而批量重做现有页面。

### 7.1 已确认结论

基于当前观察样张，在用户公司使用的 2K 显示器上，先收敛出这组临时标准：

1. `16px` 是新页面允许的最小字号，新页面文本不得低于这个值。
2. 新页面主正文默认应高于 `16px`，优先按 `17px ~ 18px` 评估，再根据页面密度收敛。
3. 新页面的按钮文案、tab 文案、输入框文字不能低于 `16px`。
4. 新页面里的按钮和输入框高度，默认优先使用 `40px`。
5. 新页面说明文字、正文段落、设置说明、表单帮助文本的行高与段落松紧，必须等于或高于设置页“白天、跟随系统、夜间三种显示方式”说明文本的当前标准。
6. 上述参考文本当前实现为：
   - 字号：`16px`
   - 行高：`1.6`
   - 标题与说明之间的上间距：`6px`
   - 位置：`src/views/settings/index.tsx` 中的 `.setting-desc`
7. 页面标题默认不要低于 `24px`，小区块标题默认优先从 `20px` 开始考虑。
8. 主要可点击图标即便视觉上只有 `16px ~ 18px`，热区也尽量保持 `32px` 以上。

### 7.2 当前暂不定稿的部分

下面这些项本轮样张还不够有区分度，先不要在规范里写死：

- 目录树节点字号（但仍不得低于 `16px`）
- 目录树节点行高
- 右键菜单项高度
- 列表行高

这些等下一轮更贴近真实场景的样张确认后，再补成正式标准。

## 8. 后续落地方式

建议按下面顺序推进，而不是一次性全项目大改：

1. 先做一张 UI 校准页，只做展示，不做复杂逻辑。
2. 你在自己的显示器上看第一轮样张，确认“舒服的档位”。
3. 确定后再把字号、行高、热区、间距整理成 token 或常量。
4. 后续优先改高频区域：
   - 目录树
   - 浏览器头部
   - 列表 / 右键菜单
   - 弹框
   - 工具页
5. 最后再逐步收口到其他页面。

当前第一轮临时样张已经放在：

- `/settings` 软件设置页顶部的“显示清晰度校准”区域

这块区域的目标只是帮助观察和回收参数，不代表最终视觉设计已经定稿。

## 9. 维护规则

出现以下情况时，必须更新本文：

- 新增了真正的全局字号 / 间距 / 密度 token
- 完成了 UI 校准页，并且第一轮观察结果已经确定
- 某个高频页面证明这里的候选档位不成立
- 主开发显示器、缩放比例或主题策略发生变化
