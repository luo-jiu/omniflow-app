# OmniFlow App 显示与可读性基线

更新时间：2026-08-20
适用范围：`omniflow-app` 前端页面、工作区、内置浏览器、目录树、弹框、工具页和后续新页面的显示尺寸、字号、密度与可读性校准。

## 1. 概述

当前项目里已经出现过两类相反但相关的问题：

- 页面在主开发显示器上看起来偏小
- 早期开发长期依赖 Chromium 页面缩放，导致恢复 `Cmd/Ctrl+0` 后界面整体偏大
- 不同页面的字号、行高、按钮密度不一致
- 同样是“工具栏”“列表”“说明文案”，不同页面给出的视觉重量差异过大
- 暗色和亮色主题下，有些文字和按钮虽然“能看见”，但不够舒服和明确

这份文档的目标不是立刻把全项目一夜之间统一，而是先固定一套可讨论、可观察、可逐步落地的基线：

1. 先明确哪些显示参数必须统一
2. 先给出一版候选档位
3. 先定义一张“观察样张页”该展示什么
4. 后续页面改造时，优先往这套基线靠，而不是继续每页自由发挥

## 2. 当前结论

### 2.1 这不是“纯字体”问题

“页面看起来小”通常不是单独某个 `font-size` 引起的，而是几件事叠在一起：

- 正文偏小
- 行高太紧
- 图标小，但点击热区也小
- 工具栏高度不够
- 列表行高不够，导致内容显得挤
- 面板 padding 太小，视觉呼吸感不足
- 次级文本和禁用态太灰，视觉上像缩进去了一层

所以后续不能只盯着字号，而要把“字号 + 行高 + 间距 + 控件高度 + 对比度”当成一组来定。

### 2.2 当前默认假设

2026-05-03 起，显示基线进入“恢复 `100%` 页面缩放”的迁移阶段：

- 主要观察场景：桌面端主工作区
- 视觉参照为：先按 `Cmd/Ctrl+0` 恢复默认页面缩放，再按 4 次 `Cmd/Ctrl-` 后得到的历史舒适尺寸
- 这组舒适尺寸约等于 Chromium `67%` 页面缩放下的观感
- 后续应通过真实 CSS 尺寸迁移，让 `100%` 页面缩放尽量接近上述观感
- 应用级 `Cmd/Ctrl +/-/0` 页面缩放已禁用，不再作为 UI 尺寸比对手段；内置浏览器网页自身缩放暂不纳入这条限制
- 已确认的参照样张是 `src/views/settings/index.tsx` 设置页；主工作区按同一密度继续收敛
- 旧的“新页面文本不得低于 `16px`”不再作为迁移期硬约束；工作区高频控件可使用 `10px ~ 13px` 文案，但必须保证行高、截断、点击热区和主题对比度可用
- 目录树右键菜单可在通用 `directory-context-menu` 基础上叠加更紧凑样式，但必须沿用同一套颜色、圆角、hover 和图标槽语义，只压缩宽度、行高、padding 与图标尺寸
- 目录树右键触发的弹框 / overlay（新建文件、上传确认、删除确认、属性、重命名输入）必须使用紧凑工作区基线：标题约 `14px`、正文约 `12px`、按钮高约 `28px`、输入框高约 `24px ~ 28px`，不能回到旧缩放时代的 `16px ~ 18px` 正文和 `40px` 按钮
- 业务二次确认统一通过 `src/components/ui/compact-confirm.ts` 的 `openCompactConfirm` 打开，由 `src/assets/css/common.less` 的 `.app-compact-confirm` 提供 `360px` 最大宽度、`14px` 标题、`12px` 正文和 `28px` 按钮基线；除明确需要更宽内容并同步记录原因外，不得直接调用 Semi 默认 `Modal.confirm`
- 顶部滑入反馈（Semi Toast / Notification）按历史舒适尺寸收敛到约 `67%`：Toast 约 `10px / 14px`、`8px` 上下 padding、最大宽度约 `348px`；Notification 标题约 `11px`、正文约 `10px`。这类全局反馈只在 `src/assets/css/feedback.less` 统一调整，业务调用点不单独写尺寸

- 当前项目里已有一份已落地的 [ui-font-size-reference.md](/Users/loyce/personal/omniflow/omniflow-app/docs/ui-font-size-reference.md)，它记录了视频页的实际处理。
- 那份文档继续保留，作为“已发生事实”。
- 本文负责更上层的“全局候选基线”和“后续校准清单”；历史字号参考只作为迁移前事实，不再压过当前 `100%` 缩放迁移。

## 3. 第一版候选字号层级

下面不是最终定稿，而是建议先做成观察样张的候选档位。

### 3.1 字号梯度

| 层级 | 建议字号 | 主要用途 | 当前建议 |
| --- | --- | --- | --- |
| XS | `13px` | 极轻量辅助信息、时间戳、极短标签 | 慎用，不做正文 |
| S | `14px` | 次级说明、meta、弱提示、表格次文本 | 可用，但不做主要交互正文 |
| M | `15px` | 目录树、tab、输入框、按钮文案、常规列表正文 | 推荐作为桌面高频默认值 |
| L | `16px` | 正文段落、表单说明、普通面板正文 | 推荐作为宽松正文值 |
| XL | `18px` | 次级标题、关键值、工具区重点说明 | 推荐作为强调层 |
| 2XL | `20px` | 小区块标题、重要操作区标题 | 推荐作为模块标题层 |
| 3XL | `24px` | 页面标题、空状态标题 | 推荐作为页面级标题起点 |
| 4XL | `28px` | 强页面标题、欢迎区标题 | 仅少数页面使用 |

### 3.2 暂时不建议的做法

- 大面积正文继续使用 `12px` 或 `13px`
- 主要按钮文案用 `13px`
- tab 文案、目录树文案、URL 栏文案低于 `15px`
- 通过把文字缩小来“塞更多信息”
- 暗色模式里依赖更灰的文字来制造层级

## 4. 第一版候选行高与控件高度

### 4.1 行高

| 内容类型 | 建议值 |
| --- | --- |
| 紧凑标签 / 单行按钮 | `1.2 ~ 1.3` |
| 常规正文 / 列表项 | `1.45 ~ 1.6` |
| 标题 | `1.2 ~ 1.35` |
| 多行说明文本 | `1.6 ~ 1.75` |

### 4.2 常见控件高度候选

| 控件 | 候选值 | 备注 |
| --- | --- | --- |
| 顶部工具栏按钮热区 | `32px ~ 36px` | 图标可以小，热区不能太小 |
| 输入框高度 | `36px ~ 40px` | URL 栏、搜索框、普通输入尽量统一 |
| 列表 / 树节点行高 | `34px ~ 40px` | 目录树和右键菜单不能过瘦 |
| 表格常规行高 | `40px ~ 44px` | 避免整页显得发虚且难点 |
| 面板标题区高度 | `44px ~ 52px` | 区块分隔更稳定 |

## 5. 观察样张页应该包含什么

为了让你在自己的显示器上直接判断“哪组更舒服”，建议做一张专门的 UI 校准页。第一页不追求复杂逻辑，只追求对比清楚。

建议样张页至少包含下面几块：

### 5.1 浏览器头部样张

- 标签栏文案：`14 / 15 / 16`
- URL 输入文案：`14 / 15 / 16`
- 工具栏图标：`16 / 18 / 20`
- 头部按钮热区：`32 / 34 / 36`

观察点：

- 哪一档在你当前显示器上最像“正常浏览器”
- 哪一档最不容易显得发虚、细碎

### 5.2 目录树样张

- 节点文案：`14 / 15 / 16`
- 次级计数或路径：`13 / 14 / 15`
- 节点行高：`34 / 36 / 38 / 40`
- 右键菜单宽度、菜单项上下 padding、图标尺寸

观察点：

- 哪组最容易连续扫读
- 哪组在不打开全部节点时仍不显拥挤

### 5.3 列表 / 卡片样张

- 列表标题：`16 / 18`
- 主信息：`15 / 16`
- 次信息：`14 / 15`
- 按钮文案：`14 / 15 / 16`
- 卡片内边距：`16 / 20 / 24`

观察点：

- 哪组既清楚又不脏
- 哪组更适合当前项目这种工具型桌面 UI

### 5.4 弹框 / 表单样张

- 弹框标题：`18 / 20 / 22`
- 正文：`15 / 16`
- help text：`14 / 15`
- 输入框高度：`36 / 40`
- 主按钮与次按钮对比度

观察点：

- 白天和夜间模式下，是否都足够明确
- 能否一眼看清主操作而不靠 hover 才知道能点

### 5.5 空状态 / 欢迎页样张

- 页面标题：`24 / 28`
- 描述文本：`15 / 16 / 18`
- CTA 按钮：`15 / 16`

观察点：

- 是否显得轻松、清爽，而不是又大又空或者又小又弱

## 6. 前端开发需要先定下来的项目

下面这些建议后续全部收成统一标准，不要再分散在各页面里临场决定。

### 6.1 排版层级

- 页面标题字号
- 区块标题字号
- 正文字号
- 次文本字号
- 标签 / meta 字号
- 按钮文案字号
- 输入框文字字号
- tab 文字字号

### 6.2 密度与尺寸

- 头部栏高度
- 工具栏按钮热区
- URL 栏高度
- 目录树节点行高
- 右键菜单项高度
- 列表 / 表格行高
- 弹框按钮区高度
- 常用面板 padding

### 6.3 宽度与最小尺寸

- 目录树最小宽度
- 工具面板最小宽度
- 浏览器设置页内容区最小宽度
- 弹框最小宽度
- 表单标签列宽建议
- 操作按钮最小宽度

### 6.4 图标与点击热区

- 常规图标显示尺寸
- 常规图标按钮热区
- 顶栏图标尺寸
- 列表行内图标尺寸
- 空状态插画 / 大图标尺寸

交互控件和识别槽统一使用三档圆角语义。新代码使用全局 token，旧页面在实际调整时增量迁移，不做无验证的全项目替换：

- 小圆角 `--app-radius-small: 5px`：用于菜单选项、候选项、紧凑结构项，以及无法点击、只承担识别或状态展示的图标容器。不可因为容器接近正方形就将这类静态图标槽改成正圆。
- 中圆角 `--app-radius-medium: 10px`：用于普通文字按钮和普通图标按钮，包括编辑、复制、删除等悬停后显示背景的常规操作。接近正方形的普通按钮仍保持中圆角，不自动升级为正圆。
- 大圆角 `--app-radius-large: 999px`：用于开始、停止、启用等需要常驻强调背景的特殊操作。横向按钮表现为胶囊，正方形热区表现为正圆。
- 输入框、内容卡片、列表交替底色和菜单容器不直接套用上述按钮语义，应根据自身结构单独选择圆角。

圆角由交互语义决定，不由元素宽高单独决定。同一个动作在常态、悬停、聚焦和执行中不得切换圆角档位，避免背景形状跳变。

高频 `14px～20px` 小图标的清晰度、整数网格、视觉包围盒和自制 SVG 规则见 `docs/small-icon-rendering-guidelines.md`。小图标不得只按 CSS 宽高判断是否一致，也不得把不适合目标尺寸的复杂图标直接缩小后依靠放大倍率补救。

#### 6.4.1 目录树图标槽位

目录树节点图标必须先统一“槽位”，再按图标自身形态做极小视觉校准：

- 目录树**文件 / 默认目录 / 内置类型 / 归档类型**四类图标统一放进 `15px * 15px` 槽位，全部走 `<img>` from custom material SVG 这一条渲染路径，不再分流到 Semi 内置 `IconFolder`。
- 图标尺寸的单一来源是 `src/features/file-explorer/utils/file-node-icon.tsx` 顶部的 `TREE_ICON_SIZE = 15` 常量；CSS 的 `15px` 字面量必须与之一致，禁止再出现"img 写 20、CSS 写 15"这类双源声明。
- 图标元素必须使用 `object-fit: contain`，不得只依赖 SVG 自身 `viewBox` 或 `width/height` 来决定最终视觉大小。
- 目录树前缀槽位（展开箭头、加载态和叶节点占位）统一为 `22px * 22px`，叶节点不得继续使用 Semi 默认的 `12px + 8px` 槽位，否则没有箭头的节点会向左偏移。
- 展开箭头的可见 glyph 应小于 `15px` 节点图标（当前使用约 `10px` 的线性 `ChevronRightStroked`），但点击热区仍保持完整的 `22px` 槽位；展开/折叠只旋转 glyph，不改变槽位尺寸，也不显示独立 hover 背景。垂直位置按实际字形像素而非 SVG / flex 外框校准，当前箭头相对槽位上移 `1.3px`，文件夹图标不跟随补偿。
- 箭头区域必须自行截断 `dblclick` 冒泡，避免连续单击生成的双击事件再次触发行级目录切换；不得用固定毫秒 guard 猜测操作系统的双击阈值。
- 内置类型图标的视觉面积参考默认文件夹（`folder-base.svg`）：主体图形不应明显高过同一行的默认文件夹图标，也不应比普通文件夹小一圈。
- **所有目录类图标都必须提供闭合与展开两态**，例如 `folder-base.svg` / `folder-base-open.svg`、`folder-video.svg` / `folder-video-open.svg`；开合图标必须通过 Tree 节点的 `expanded` 渲染参数切换，不得把展开状态写回 `treeData`，否则 Semi 会将结构更新视为数据变化并取消展开动画。
- 首次懒加载必须通过 pending expand 与 `useLayoutEffect` 确认 children 已提交，再于下一帧写入 `expandedKeys`；不得只用 `requestAnimationFrame` 猜测 React commit。这样用户只会看到数据就绪后的完整展开动画，不会先展开空容器再补内容。
- 不同 SVG 的有效图形面积不一致时，只允许在类型 class 上用 `0.5px ~ 1.5px` 的 `padding` 做感知大小校准，例如 `comic-folder`、`asmr-folder`、`audio-folder`、`video-folder`、`gallery-folder`、`default-folder`。本仓库当前所有目录类图标共享 0.5px 基准。
- 新增目录树语义图标时，必须同时检查默认目录、漫画归档、ASMR 归档、音频归档和视频归档同屏展示效果，避免出现某个图标因为 SVG 内容铺满画布而明显偏大。

### 6.5 明暗主题可见性

- 主文本对比度
- 次文本对比度
- 禁用态的“还能看见但明确不可点”的表现
- 激活态是不是靠背景、边框、文字色还是三者组合
- 白天主题是否“发灰发脏”
- 夜间主题是否“发糊发闷”

### 6.6 截断与折行

- tab 文案的省略策略
- 目录树过长名称的省略策略
- URL、路径、资源名称的展示优先级
- 表格列是否允许换行
- 描述文本在什么情况下必须折行而不是缩小字号

### 6.7 文件预览 tab 宽度与动效

- 文件预览 tab 不再按内容撑宽，默认宽度为 `168px`，最小宽度为 `96px`。
- 当可用宽度不足时，tab 应先整体等比例压缩到最小宽度；最小宽度仍放不下时，再使用已有横向滚动条。
- 拖拽重排 tab 时使用上一帧位置做布局过渡；关闭 tab 时先触发真正关闭，再由 tab bar 保留本地退出快照折叠宽度，让相邻 tab 通过 flex 布局自然收回，避免关闭瞬间出现旧位置残影，同时不延迟媒体释放链路。
- tab 前缀图标复用目录树图标解析，不额外添加彩色胶囊或文字标签。

### 6.8 工作区滚动条

- 高频工作区的普通滚动容器默认使用窄滚动条，WebKit / Electron 下横纵尺寸优先取 `8px`；轨道保持透明，避免在暗色内容区出现突兀的亮色边带。
- 滑块颜色必须复用 `--app-scrollbar-thumb`、`--app-scrollbar-thumb-hover` 和 `--app-scrollbar-track` 主题 token，不在业务组件中写死明暗色值。
- 滚动条右下角交汇区应与轨道同为透明，横纵滚动条同时出现时不能产生白色方块。
- 不设置全局 `*::-webkit-scrollbar` 规则。PDF、漫画、图集、编辑器等滚动模型不同，应由实际滚动容器局部应用；当多个同类容器的显隐和交互规则稳定一致后，再抽 styled-components 共享片段。

## 7. 当前页面准入标准

这套标准约束后续新页面和新模块；现有页面按使用频率逐步迁移，不要求一次性批量重做。

### 7.1 已确认结论

1. 不再设置全项目统一的 `16px` 最小字号或 `40px` 控件高度。页面必须先区分高频工作区、普通表单和阅读型内容，再选择对应密度。
2. 高频工作区的短标签、辅助文案和紧凑按钮允许使用 `10px ~ 13px`，但必须同时保证行高、截断、点击热区和明暗主题对比度。
3. 普通正文和阅读型内容优先沿用第 3、4 节候选层级，不得仅为塞入更多内容而缩小字号。
4. 业务二次确认和目录树 overlay 使用第 2.2 节的紧凑基线；复杂表单 Modal 继续按内容长度和操作密度独立定宽。
5. 图标的视觉尺寸与点击热区分开控制。主要图标按钮应保持稳定热区，不得因图标缩小而变得难以点击。
6. 所有新页面都必须在 `100%` 页面缩放下检查文字折行、容器溢出以及亮色、暗色主题可见性。

### 7.2 仍需按真实场景校准的部分

- 目录树节点字号与行高
- 右键菜单项高度
- 列表与表格行高
- 普通表单按钮和输入框高度

这些参数不得先写成新的全局硬标准；应在真实高频页面中验证稳定后，再沉淀为共享 token 或组件规则。

## 8. 后续落地方式

建议按下面顺序推进，而不是一次性全项目大改：

1. 先做一张 UI 校准页，只做展示，不做复杂逻辑。
2. 你在自己的显示器上看第一轮样张，确认“舒服的档位”。
3. 确定后再把字号、行高、热区、间距整理成 token 或常量。
4. 后续优先改高频区域：
   - 目录树
   - 浏览器头部
   - 列表 / 右键菜单
   - 弹框
   - 工具页
5. 最后再逐步收口到其他页面。

当前第一轮临时样张已经放在：

- `/settings` 软件设置页顶部的“显示清晰度校准”区域

这块区域的目标只是帮助观察和回收参数，不代表最终视觉设计已经定稿。

## 9. 维护规则

出现以下情况时，必须更新本文：

- 新增了真正的全局字号 / 间距 / 密度 token
- 完成了 UI 校准页，并且第一轮观察结果已经确定
- 某个高频页面证明这里的候选档位不成立
- 主开发显示器、缩放比例或主题策略发生变化
