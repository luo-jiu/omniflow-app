# 内置类型与归档模式说明

更新时间：2026-05-06
适用范围：`features/file-explorer`、`features/file-viewer`、`features/archive-viewer`、`views/library/detail/` 中与节点内置类型、归档模式、目录树限制和视图选择相关的代码。

## 1. 概述

OmniFlow 里有一组不是通用前端术语、而是项目自己定义出来的业务概念：

- 内置类型
- 归档模式
- 内置类型目录
- 归档目录
- 打开原始目录

这些概念不是“UI 装饰”，而是会直接影响：

- 目录树图标和右键菜单
- 目录是否允许直接展开
- 文件是否允许拖拽上传或作为移动目标
- 文件打开后进入哪类 viewer

如果后续开发者不了解这套概念，只看组件名，很容易误以为这只是图标或标签系统。

## 2. 核心概念

### 2.1 内置类型

当前代码里的 `builtInType` 主要有 5 个值：

- `DEF`
  - 默认模式，不附加项目语义
- `COMIC`
  - 漫画目录语义
- `ASMR`
  - ASMR 目录语义
- `VIDEO`
  - 视频目录语义；只能设置到文件夹，不能设置到文件
- `AUDIO`
  - 通用音频目录语义；只能设置到文件夹，不能设置到文件

它可以理解为“给节点附加一种项目内约定的展示/处理语义”。

### 2.2 归档模式

当前代码里的 `archiveMode` 主要有 2 个值：

- `0`
  - 关闭
- `1`
  - 开启

归档模式当前只在目录菜单中暴露，不给文件单独展示。

它不是独立类型，而是“附着在内置类型目录上的附加行为开关”。

### 2.3 三种常见目录状态

当前最常见的目录状态可以概括为：

- 普通目录
  - `builtInType = DEF`
  - `archiveMode = 0`
- 内置类型目录
  - `builtInType != DEF`
  - `archiveMode = 0`
- 归档目录
  - `builtInType != DEF`
  - `archiveMode = 1`

其中“内置类型目录”和“归档目录”在行为上是两类不同对象，后续不要混用。

## 3. 当前用户可见行为

### 3.1 右键菜单

目录树右键菜单里当前会暴露：

- 内置类型
  - 文件夹：默认 / 漫画 / ASMR / 视频 / 音频
  - 文件：默认 / 漫画 / ASMR；`VIDEO` / `AUDIO` 不对文件展示
- 归档模式
  - 仅文件夹展示关闭 / 开启

额外行为：

- `COMIC` 目录会出现“按名称排序”
- `AUDIO` 目录会出现“按名称排序”
- `AUDIO` 归档目录和其直属音频文件会出现“显示隐藏文件 / 隐藏文件”，用于临时显示同名字幕文件
- 归档目录会出现“批量设置内置类型”
- 非归档的内置类型目录会出现“打开原始目录”

### 3.2 图标

目录图标当前由内置类型和归档模式共同影响：

- `DEF`（默认目录）使用经典黄色文件夹图标 `folder-base.svg` / `folder-base-open.svg`
- `COMIC` 非归档目录使用漫画文件夹图标；`COMIC + archiveMode=1` 使用漫画归档文件夹图标
- `ASMR` 非归档目录使用 ASMR 文件夹图标；`ASMR + archiveMode=1` 使用 ASMR 归档文件夹图标
- `VIDEO` 非归档目录使用视频文件夹图标；`VIDEO + archiveMode=1` 使用视频归档文件夹图标
- `AUDIO` 非归档目录使用音频文件夹图标；`AUDIO + archiveMode=1` 使用音频归档文件夹图标
- 五类目录图标都必须提供闭合 / 展开两态，目录树展开后切到对应 `*-open` 图标；切换由 `directory-tree/index.tsx` 的 `patchNodes` 根据 `expandedKeys` 完成
- 归档与非归档在所有内置类型目录上必须有图标区分：普通媒体文件继续按扩展名使用 `video.svg` / `audio.svg` 等文件图标，非归档内置目录使用 `folder-{type}.svg`，归档目录使用 `folder-{type}-archive.svg`；归档语义同时保留目录树文本绿色加粗（`tree-node-text-archive`）
- 归档目录图标统一使用右下角绿色归档盒角标；同为音频符号的 `ASMR` 与 `AUDIO` 保持相同的音符图形，但 `ASMR` 使用樱花粉文件夹与高对比白色音符，`AUDIO` 使用红色文件夹与浅红音符，避免只靠名称判断
- `VIDEO` 非归档目录和归档目录使用同一套蓝青色视频文件夹主体；归档目录仅额外增加右下角绿色归档盒角标
- 未知内置类型会显示警告图标
- 在某些归档语义不匹配的文件上会显示警告图标

五类目录图标统一进 15px × 15px 槽位、统一走 `<img>` from custom SVG 路径、统一 0.5px 基础 padding，不再走 Semi 内置 `IconFolder`。详见 `docs/ui-display-readability-baseline.md` §6.4.1。

图标不是单纯装饰，而是在向用户暴露“当前节点被系统按什么语义理解”。

### 3.3 目录展开与原始目录

当前代码里，非归档的内置类型目录默认不会像普通目录那样直接展开。

用户如果想看它的原始目录结构，需要显式通过右键选择“打开原始目录”。

这条规则的目的是把“项目语义目录”和“底层原始目录”区分开，避免用户把它当普通文件夹直接钻进去。

当前 `VIDEO` 非归档目录没有单独的普通集合 viewer。
双击时会优先打开目录下首个视频资源；如果要浏览真实目录结构，仍然需要通过“打开原始目录”进入。

`VIDEO` 内置目录下的视频文件、图片文件和字幕文件都属于合法资源：视频是主媒体，图片通常作为封面，字幕作为伴随资源。其它不相关文件仍会显示警告图标。

当前 `VIDEO` 归档目录展示的是直属视频单元卡片：

- 新规则优先支持直属 `VIDEO` 文件夹：文件夹本身是卡片，内部第一个视频文件作为主媒体，第一个图片文件作为封面，同级字幕文件作为伴随资源计数
- 如果直属子目录本身也是 `VIDEO` 归档目录，则作为“合集”卡片展示；双击合集卡片会直接打开合集内排序最前的可播放视频，并把该合集的一代视频单元作为 `VideoViewer` 播放列表传入，播放页底部控制条可展开列表气泡切换集数；只看当前父子关系，不在父层递归拉平孙级内容；合集封面沿用视频单元规则，支持 `coverNodeId` 和合集目录第一代图片文件
- 为兼容历史数据，直属视频媒体文件仍会作为卡片展示；同名封面 / 字幕会按文件名辅助匹配
- 不把 `mp3` 等音频算成视频卡片
- 如显式写了 `coverNodeId` 就优先用它；否则用视频文件夹内封面、同名封面或视频首帧预览兜底
- 从视频归档卡片打开普通视频 viewer 时，字幕文件会作为库内字幕候选传入；存在多个字幕时默认加载排序最靠前的字幕，用户仍可在视频操作台切换

当前 `AUDIO` 归档目录展示的是直属音频媒体文件卡片：

- 只认音频媒体资源，不把字幕、文本、视频或图片算进卡片
- 子音频文件当前不要求再单独设置 `builtInType = AUDIO`
- 目录树中同级同名字幕默认折叠隐藏；通过右键临时显示时，字幕紧贴对应音频文件下方

### 3.4 上传与移动限制

当前代码里，归档目录有明显限制：

- 不支持拖拽上传
- 允许作为移动目标；用户可以拖入、拖出或在目录内排序，后端仍保留不能移动到自身 / 子节点等通用移动安全校验

拖拽上传被拦住时，界面会提示用户改用右键上传。

## 4. 当前业务约束

### 4.1 先设内置类型，再开归档模式

当前代码明确限制：

- 如果 `builtInType = DEF`
- 则不能直接开启 `archiveMode = 1`

界面提示是“请先设置内置类型，再开启归档模式”。

### 4.2 设置回 `DEF` 会自动关掉归档模式

当前代码里，如果一个目录原本在归档模式中，而用户把内置类型改回 `DEF`，系统会自动把归档模式一起关闭。

这说明：

- `archiveMode` 不能脱离内置类型单独存在
- `DEF + archiveMode = 1` 不是合法长期状态

### 4.3 批量设置内置类型只对归档目录生效

“批量设置内置类型”当前只允许：

- 节点是文件夹
- 且是归档模式
- 且内置类型不是 `DEF`

这说明它本质上是归档目录的结构整理工具，不是通用批量编辑能力。

## 5. 和文件预览的关系

这里最容易误解的一点是：

- `builtInType / archiveMode` 是节点配置语义
- `fileType` 是文件打开后进入 viewer 的分发类型

它们相关，但不是同一个层级。

可以这样理解：

- 内置类型和归档模式决定目录树如何理解一个目录
- 文件打开链路再把最终文件分发成 `comic / asmr / video_archive / audio_archive / comic_archive / asmr_archive` 等 viewer 类型

所以后续如果要改：

- 节点语义
  - 优先看 `file-explorer`
- 预览分发
  - 优先看 `file-viewer` / `archive-viewer`

不要把这两层揉在一起改。

## 7. 验证方式

涉及这套概念时，至少手工验证：

1. 目录右键能看到内置类型与归档模式菜单。
2. `DEF` 目录不能直接开启归档模式。
3. 归档目录改回 `DEF` 后会自动关闭归档模式。
4. 非归档内置类型目录需要通过“打开原始目录”进入原始结构。
5. 归档目录拖拽上传会被拦截。
6. 归档目录可以作为移动目标，拖入、拖出和同层排序都应正常走通。
7. `COMIC` 目录的额外动作和图标仍然正常。
8. `VIDEO` 内置类型只允许设置到文件夹；文件右键不展示视频内置类型入口。
9. `VIDEO` 归档目录双击会进入独立的视频归档页，视频文件夹卡片双击后打开其内部主视频。
10. `VIDEO` 归档内的直属子视频归档会显示“合集”标签，双击后直接播放合集内排序最前的视频；普通视频 viewer 底部应出现播放列表按钮，可在气泡里切换同合集集数。
11. `AUDIO` 归档目录双击会进入独立的音频归档页，目录树默认隐藏同名字幕文件，右键可临时显示或再次隐藏。
