# M2 插件独立工具工作区

更新时间：2026-09-23

状态：本批限定的 macOS 开发环境范围已验证完成。M1 已阶段提交（`8464daf`）；M2 提供插件独立工具页面，复用既有执行、批准和文件产物链路。本文记录当前能力与验收边界，不代表全部插件长期路线已完成。

## 1. 当前能力

让已安装插件在工具导航中提供独立页面，完成文件处理参数选择、内容预览和另存。复用现有 JSON 转换样板，服务资料处理和再利用。文件身份、权限、批准、提交事实和历史继续由宿主维护，遵守[项目长期方针](../../PROJECT_PRINCIPLES.md)及 [M1 手动执行](plugin-system-m1-manual-commands.md)。

SDK、Manifest 和安装目录支持工作区贡献，工具导航动态显示已安装且获准的页面。宿主提供源文件和输出位置，插件绘制业务参数与预览；main 绑定账号、资料库、单个源文件和当前包指纹，请求准备时调用 M1。既有 JSON 转换样板已增加顶层字段勾选、格式参数和有界结果预览，未新增重复样板。

## 2. 最小契约

SDK 为 0.7.0；wire/sdkVersion 仍为 1，Manifest 为 2。可选 `workspaces` 每项为 `id/title/entry/commandId`，最多 8 项，名称在包命名空间内并与其他贡献唯一；激活条件为 `workspace:<id>`。入口必须是包内已校验 HTML。命令必须来自同包、关联单文件只读或 `file-output` Tool；批量元数据改名、目录和无资源命令不纳入首批工作区。

插件上下文使用独立 `kind: workspace`，含贡献 ID、命令 ID、主题及当前资源不透明句柄。工作区只获得当前单文件读取、生命周期和 `workspace.prepare`；不复用 Viewer 阅读状态，也不取得目标节点、凭据、任意 HTTP、主窗口 DOM 或提交接口。

`prepareWorkspaceCommand(parameters)` 只提交业务参数并快速返回宿主请求 ID。源文件绑定于打开页面时；文件产物命令要求宿主先选定输出目录和文件名，受理准备请求时冻结该目标，再异步调用既有 M1 准备链。broker 拒绝资源身份、目标和原型相关参数键，并复核读取权限与源版本；业务参数仍通过所关联 Tool 的 schema 校验。返回请求 ID 不代表准备成功，更不代表已经保存。准备结果、失败和最终批准在可信宿主区域显示。

## 3. 状态和权限

安装事实和可用贡献仍由 PluginManager 持有。工作区可用性来自包启用、未阻断及关联命令所需能力批准，不依赖 Agent Tool 批准。更新、回滚、撤权、安全模式与卸载统一停止旧实例。

工具导航沿用稳定 ID、排序和暂不可用贡献恢复规则。宿主组件持有未提交的文件选择和目标草稿；插件持有未提交的业务交互与预览。main 持有原生实例、资源权限、包指纹和一次准备请求，M1 持有唯一执行与提交记录。没有新的执行历史或 Agent 会话。

目录树当前单文件选择可预填宿主源文件草稿；用户仍须点击“打开工具”，才加载插件并授予该源读取范围。更换源、切换工具、离库、注销和关闭窗口释放视图与句柄，未提交页面草稿不承诺恢复。已有 M1 执行记录保留；离库和注销沿用 M1 取消/结算语义。准备期间同实例只受理一个请求，目标变更不能改写在途请求。准备、待批准、提交和结果未知期间隐藏原生页面，宿主可在执行记录创建后立即提供取消入口。

## 4. 隔离与兼容

使用现有 WebContentsView、专用 preload、来源路由、固定 session 池、CSP、看门狗和实例预算。工作区与 Viewer/Tool 同享资源限制；不复制无限实例池或开放通用 IPC。布局和主题由可信宿主投影，目录选择浮层显示期间隐藏原生页面。

原 Viewer、Agent Tool、M1 统一表单与旧包保持兼容。新清单在不支持它的旧宿主上明确拒绝。本批不改后端 API、数据库或现有内置工具状态 owner。

## 5. 验证结果

自动化覆盖贡献引用/入口校验、当前权限与资源版本、旧实例和迟到请求、异步准备不重复提交、目标冻结、停用释放、导航恢复与可信批准区域。2026-09-23 阶段收尾的 `npm run lint`、`npm test`、`npm run build` 均通过；全量测试为 421 文件、3282 项通过，3 文件、7 项跳过，已包含 renderer API 迟到打开检查。SDK 0.7.0 和 JSON 样板已通过仓库外离线构建及 ZIP 打包。

macOS 实际验证只使用非第一个资料库 Win（libraryId=3）、本机 local-minio 和专用合成文件。安装 `example.json-transform@0.1.3`，启用读取及文件产物能力，保持 Agent Tool 未批准，验证如下：

- 工具导航出现“JSON 转换”；目录树选中的源文件正确预填，显式打开后加载独立页面。自选字段但未选任何项时显示错误并禁止准备；仅选择 `headers` 时预览为 49 字节。
- 打开宿主目录选择浮层时原生页面隐藏，取消后恢复同一页面及字段选择。点击“准备另存”后由宿主显示准备状态与完整产物批准卡，插件页面隐藏。
- 首次拒绝后执行记录为 cancelled，没有目标回执或提交记录；返回原页面仍保留字段选择。再次准备同一目标并批准后，记录为 completed，上传回执为 committed，目录自动出现新文件。
- 新文件 `omniflow-m2-workspace-20260923.json` 为节点 18524（父节点 15971），产物卡记录 49 字节。切回内置文件预览后，实际读取内容仅含 `headers: ["名称", "内容"]`，与页面预览一致，插件页面不再显示。此次未另行下载对象作独立字节哈希核验。

JSON 页面与 Tool 共用转换逻辑；源文件最大 4 MiB、产物最大 1 MiB，预览超过 24,000 字符明确标注截断，真实产物完整输出或明确超限失败。详细字段限制和 JSON 数值语义见[样板说明](../samples/json-transform/README.md)。

## 6. 保留边界与维护规则

本轮没有手验亮色主题、极窄布局、执行中实时撤权及真实故障/重启后的回执查询；撤权和异步释放已有自动化覆盖。发行包、Windows/Linux、小时级性能、任意本机程序、后台自动任务和更多主题控制不纳入本批。

后续改动须继续复用 M1 执行记录和批准链，不在工作区维护第二份执行事实或开放直接提交。修改贡献协议、资源授权、原生视图遮挡或生命周期时，同步更新本文及[验证矩阵](frontend-validation-matrix.md)，并重验“打开工具→交互预览→拒绝/批准→新文件预览”代表路径。
