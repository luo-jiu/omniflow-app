# 资源创建向导 — 规划草案

> **临时文档**。本文件只记录“未来要做”的资源创建向导规划，不是长期架构文档。功能完成后，应删除本文件，并把最终结论回写到 `docs/built-in-type-and-archive-mode.md`、`docs/file-explorer-file-viewer-boundary.md`、`docs/viewers/archive-viewer.md` 或对应 viewer 文档。

更新时间：2026-05-08

## 1. 背景

内置类型和归档模式逐渐变复杂后，当前创建结构化资源的流程过于手工：

1. 先创建普通文件夹。
2. 上传视频、图片、字幕、歌词、漫画图片或章节文件夹。
3. 再右键设置内置类型。
4. 需要归档时继续右键开启归档模式。
5. 有时还要批量设置子节点内置类型、按名称排序、补封面和伴随资源。

这个流程对“普通文件系统”是合理的，但对漫画、视频、音频、ASMR 这类有固定结构的资源对象不够友好。用户真正想做的是“创建一个视频合集 / 漫画归档 / ASMR 作品 / 音频专辑”，不是机械地拼一堆目录和右键配置。

## 2. 当前结论

建议未来做一个“资源创建向导”，它不是简单的新建文件夹弹框，而是结构化资源入口。

核心目标：

- 让用户明确选择资源类型和形态。
- 自动创建目录、设置 `builtInType` 和 `archiveMode`。
- 复用现有上传中心和目录创建能力，不另造上传状态机。
- 支持从当前选中目录默认创建，减少路径选择成本。
- 为漫画嵌套归档、视频合集、音频专辑、ASMR 作品沉淀统一入口。

不建议一开始做过强的“自动猜类型”。用户主动选择资源类型，系统按模板执行，成功率更高，也更容易解释失败。

## 3. 核心概念

### 3.1 资源类型

第一版建议支持：

| 类型 | builtInType | 说明 |
|---|---|---|
| 漫画 | `COMIC` | 漫画作品、漫画归档、漫画系列 |
| 视频 | `VIDEO` | 视频单元、视频合集、课程 / 番剧类选集 |
| 音频 | `AUDIO` | 音频歌曲文件夹、音频专辑 / 歌单归档 |
| ASMR | `ASMR` | ASMR 作品、ASMR 归档 |

普通文件 / 文件夹不一定纳入第一版，因为它们已有成熟的创建和上传入口。

### 3.2 资源形态

同一个资源类型下，至少要区分“作品单元”和“归档容器”：

| 形态 | archiveMode | 例子 |
|---|---:|---|
| 作品 / 单元 | `0` | 一本漫画、一首歌文件夹、一个视频单元、一个 ASMR 作品 |
| 归档 / 合集 | `1` | 漫画系列、视频合集、音频歌单、ASMR 归档 |

对用户显示时不要直接叫 `archiveMode`，建议叫：

- “单个作品”
- “合集 / 归档”
- “子合集”在有上下文时可作为提示，不一定是独立类型

### 3.3 导入方式

第一版建议支持三种导入方式：

| 导入方式 | 说明 |
|---|---|
| 只创建结构 | 只建目录并设置内置类型，之后用户手动上传 |
| 拖入文件 | 拖入视频、图片、字幕、音频、歌词、漫画图片 |
| 拖入文件夹 | 拖入章节、剧集、专辑、作品目录 |

“拖入文件夹”最有价值，但也最复杂。第一版可以先只做结构创建 + 拖入文件，第二版再补文件夹导入计划预览。

## 4. 建议入口

### 4.1 目录树右键

在目录树目录节点上增加：

```text
新建资源...
```

默认创建位置是当前右键目录。这个入口最自然，因为用户多数时候已经在目标目录附近。

### 4.2 工具栏按钮

可以在文件模式工具栏放一个紧凑按钮：

```text
新建资源
```

默认位置使用当前选中目录；如果没有选中目录，则使用当前资料库根目录或要求用户选择。

### 4.3 快捷键

快捷键可以后置，例如：

```text
Cmd/Ctrl + Shift + N
```

不建议第一版就强依赖快捷键。先把向导体验做顺，再给快捷键。

## 5. 向导流程

推荐做成一个分步弹框，但不要做得像安装向导那么重。

### Step 1：选择资源模板

展示类型 + 形态：

- 漫画
  - 漫画作品
  - 漫画归档 / 系列
- 视频
  - 视频单元
  - 视频合集
- 音频
  - 音频歌曲 / 单曲文件夹
  - 音频归档 / 歌单
- ASMR
  - ASMR 作品
  - ASMR 归档

### Step 2：填写基础信息

字段：

- 名称
- 创建位置
- 是否创建后打开
- 是否创建后进入原始目录

位置默认当前目录。位置选择可复用现有目录树定位 / 选择能力，第一版也可以只读默认位置，后续再做选择器。

### Step 3：导入文件

可选区域：

- 拖入文件
- 拖入文件夹
- 跳过，稍后上传

第一版如果不做导入，也可以保留这个步骤的设计，但 UI 暂时隐藏。

### Step 4：预览创建计划

展示系统将执行什么：

```text
创建目录：某某课程
设置内置类型：VIDEO
开启归档模式：是
上传文件：12 个
自动识别封面：cover.jpg
自动识别字幕：3 个
```

预览计划很重要，它能避免系统“自作聪明”导致用户不理解。

## 6. 类型模板建议

### 6.1 漫画

#### 漫画作品

目标结构：

```text
作品名/
  001.jpg
  002.jpg
  ...
```

执行：

- 创建目录
- 设置 `builtInType=COMIC`
- 设置 `archiveMode=0`
- 上传图片
- 可选按名称排序

#### 漫画归档 / 系列

目标结构：

```text
系列名/               COMIC + archiveMode=1
  第 01 卷/           COMIC + archiveMode=0
  第 02 卷/           COMIC + archiveMode=0
```

执行：

- 创建父目录
- 设置 `builtInType=COMIC`
- 设置 `archiveMode=1`
- 如果导入多个文件夹，默认把每个文件夹作为直属漫画作品，设置 `COMIC + archiveMode=0`
- 后续漫画归档嵌套支持后，直属 `COMIC + archiveMode=1` 子目录可以作为合集卡片进入下一层归档

### 6.2 视频

#### 视频单元

目标结构：

```text
视频名/               VIDEO + archiveMode=0
  视频名.mp4
  cover.jpg
  视频名.srt
```

执行：

- 创建目录
- 设置 `builtInType=VIDEO`
- 设置 `archiveMode=0`
- 上传视频、封面和字幕
- 视频归档页会把目录作为一个视频卡片，`mediaNodeId` 指向内部视频文件

#### 视频合集

目标结构：

```text
合集名/               VIDEO + archiveMode=1
  第 01 集/           VIDEO + archiveMode=0
  第 02 集/           VIDEO + archiveMode=0
```

执行：

- 创建父目录
- 设置 `builtInType=VIDEO`
- 设置 `archiveMode=1`
- 导入多个视频文件时，第一版可选择：
  - 直接放在合集根目录，走历史兼容视频文件卡片
  - 或为每个视频创建一个 `VIDEO` 单元目录
- 更推荐长期采用“每集一个目录”的结构，便于封面、字幕、多音轨等伴随资源管理

后续视频播放器可以把合集播放列表显示在右侧选集栏，类似 B 站交互。这个属于视频 viewer 二阶段优化，不是资源创建向导第一版必须做。

### 6.3 音频

#### 音频歌曲 / 单曲文件夹

目标结构：

```text
歌曲名/               AUDIO + archiveMode=0
  歌曲名.flac
  cover.jpg
  歌曲名.lrc
```

执行：

- 创建目录
- 设置 `builtInType=AUDIO`
- 设置 `archiveMode=0`
- 上传音频、封面、歌词 / 字幕
- 音频归档页展示为歌曲行

#### 音频归档 / 歌单

目标结构：

```text
歌单名/               AUDIO + archiveMode=1
  歌曲 A/             AUDIO + archiveMode=0
  歌曲 B/             AUDIO + archiveMode=0
```

执行：

- 创建父目录
- 设置 `builtInType=AUDIO`
- 设置 `archiveMode=1`
- 导入普通音频文件时，第一版可以直接放在根目录，沿用历史兼容
- 长期更推荐每首歌一个目录，方便封面和歌词绑定

注意：当前音频归档不展示下级 `AUDIO + archiveMode=1` 子归档为合集。向导第一版应尊重现有规则，不主动创建嵌套音频归档。

### 6.4 ASMR

#### ASMR 作品

目标结构：

```text
作品名/               ASMR + archiveMode=0
  track01.wav
  cover.jpg
  info.txt
```

执行：

- 创建目录
- 设置 `builtInType=ASMR`
- 设置 `archiveMode=0`
- 上传音频、封面、说明文件等

#### ASMR 归档

目标结构：

```text
归档名/               ASMR + archiveMode=1
  作品 A/             ASMR + archiveMode=0
  作品 B/             ASMR + archiveMode=0
```

执行：

- 创建父目录
- 设置 `builtInType=ASMR`
- 设置 `archiveMode=1`
- 导入多个文件夹时，每个文件夹作为作品目录

## 7. 实现边界

### 7.1 前端边界

建议新增 feature：

```text
src/features/resource-create-wizard/
```

职责：

- 管理向导表单状态
- 生成创建计划
- 调用目录创建、节点配置、上传中心接口
- 展示执行进度和失败项

不应该承担：

- 自己实现上传底层
- 直接操作 Electron 文件系统
- 绕过 `file-explorer/services/file.api.ts` 调后端
- 私自改目录树状态；创建成功后应走现有刷新 / 定位链路

### 7.2 后端边界

第一版可以尽量复用现有 API：

- 创建目录 / 节点
- 更新节点配置：`builtInType / archiveMode / viewMeta`
- 上传链路
- 按名称排序

如果前端编排变得很脆，可以再考虑后端新增专用 API：

```text
POST /api/v1/resources/create-plan
POST /api/v1/resources/commit
```

但不建议第一版就上专用后端资源编排 API。先证明交互有价值，再决定是否沉淀后端事务级创建。

### 7.3 上传中心边界

资源向导必须复用上传中心：

- 任务进度归上传中心 owner
- 取消 / 重试 / 并发仍按上传中心规则
- 向导只负责把文件放到正确目标目录

如果导入文件夹需要批量创建目录再上传，建议向导先生成计划，再逐步创建目标目录并把文件提交给上传中心。

## 8. 分期计划

### Phase 0：只做文档和交互草图

目标：

- 明确向导要解决的问题
- 明确不做过度自动化
- 等漫画嵌套归档和视频侧栏方案稳定后再动手

### Phase 1：最小可用资源创建

只支持：

- 目录树右键“新建资源...”
- 选择类型和形态
- 输入名称
- 在当前目录下创建目标目录
- 设置 `builtInType / archiveMode`
- 创建成功后定位并打开

不支持：

- 拖入文件
- 智能识别封面 / 字幕 / 歌词
- 复杂预览计划

这个阶段解决“创建文件夹后还要右键设类型”的麻烦。

### Phase 2：带文件导入

新增：

- 拖入文件
- 文件类型识别
- 上传到目标目录
- 视频 / 音频 / ASMR 识别封面、字幕、歌词
- 漫画识别图片页

仍然不做过度智能分组。

### Phase 3：文件夹导入和计划预览

新增：

- 拖入多个文件夹
- 按模板生成子目录计划
- 用户确认计划后执行
- 部分失败时可重试

这个阶段才真正解决“批量导入漫画章节 / 视频剧集 / ASMR 多作品”的效率问题。

### Phase 4：高级整理

候选能力：

- 自动按文件名识别集数 / 卷数 / 话数
- 自动排序
- 自动设置封面
- 自动生成标签建议
- 从浏览器捕获资源联动创建
- 导入完成后打开对应归档页

这些能力不要挤进第一版。

## 9. UI 风格建议

资源向导应该是工作型弹框，不是营销页：

- 宽度不要太窄，建议 720px 左右起步
- 左侧是步骤或模板图标
- 右侧是当前步骤表单
- 类型选择尽量用图标 + 简短名称
- 不展示长段说明，复杂解释用轻量提示
- 亮暗主题都要成立
- 不要用大面积卡片套卡片

第一版弹框可以是：

```text
标题：新建资源

[漫画] [视频] [音频] [ASMR]

形态：
( ) 单个作品
( ) 合集 / 归档

名称：
[________________]

位置：
当前目录 / 更改...

[取消] [创建]
```

## 10. 和现有工作的关系

### 10.1 漫画嵌套归档

漫画嵌套归档建议先做：

- 父级 `COMIC + archiveMode=1` 展示直属子 `COMIC + archiveMode=1` 为合集卡片
- 双击合集卡片进入子 `comic_archive`
- 普通漫画卡片仍进入 `ComicViewer`

资源向导未来可以直接创建这种结构。

### 10.2 视频合集右侧选集栏

视频当前已有合集播放列表，但入口在底部气泡里。未来可以把播放列表升级为右侧选集栏：

- 普通单视频不默认显示
- 从视频合集打开时默认显示
- 可折叠
- 与字幕 / 信息 / 工具台协调

资源向导不直接实现选集栏，但会让视频合集结构更常见，因此二者应一起考虑体验。

### 10.3 标签系统

资源向导可以未来扩展标签建议：

- 创建漫画时推荐 `COMIC + creator / series`
- 创建 ASMR 时推荐 `ASMR + genre / creator`
- 创建视频合集时推荐 `VIDEO + series / status`

第一版不要把标签强行塞进创建流程，避免向导过重。

## 11. 风险

### 11.1 过度自动化

如果系统自动猜太多，失败后用户会不知道它为什么这样建目录。对策是先用模板和计划预览，让用户确认。

### 11.2 上传状态双源

向导不能自己维护一套上传任务状态。上传任务必须继续归上传中心管理。

### 11.3 API 编排过碎

如果前端需要连续调用创建目录、设置类型、上传、排序、刷新，失败恢复会比较复杂。第一版可以接受；一旦流程稳定，应考虑后端资源创建事务接口。

### 11.4 原始目录与语义目录混淆

创建完成后是否自动打开原始目录，需要谨慎。内置类型目录默认不直接展开，向导应该尊重这个规则，必要时提供“创建后打开原始目录”选项。

## 12. 待决策问题

1. 视频合集导入多个视频文件时，默认是直接放根目录，还是为每个视频创建一个 `VIDEO` 单元文件夹？
2. 音频归档导入多首歌时，默认直接放根目录，还是每首歌一个 `AUDIO` 文件夹？
3. 漫画导入 zip / cbz 是否要在向导第一版支持？
4. 是否需要“创建后立即打开归档页”作为默认行为？
5. 是否允许向导创建到归档目录内部？如果允许，需要和现有“归档目录不支持拖拽上传”的限制统一解释。
6. 资源向导是否需要独立快捷键，还是先只放右键菜单？
7. 失败回滚策略如何设计：创建目录成功但上传失败时，是否保留目录并提示重试？

## 13. 建议下一步

短期不急着做资源创建向导。更推荐顺序：

1. 先做漫画归档嵌套，让 `COMIC` 的层级语义稳定。
2. 再决定视频播放列表是否升级为右侧选集栏。
3. 然后做 Phase 1：最小资源创建向导，只创建目录并设置 `builtInType / archiveMode`。
4. 等用户实际使用后，再做拖入文件和文件夹导入。

## 14. 完成后清理

当资源创建向导第一阶段落地后：

- 删除本文件或只保留未完成阶段。
- 把最终入口、状态 owner、API 契约回写到正式文档。
- 如果新增后端 API，同步更新后端 API 契约文档。
- 如果新增上传编排规则，同步更新上传中心 README 或专题文档。
