# 内置类型与归档的手动组织调研及实施建议

调研时间：2026-10-01；状态核对：2026-10-09
状态：手动流程仍为待实施方案；Agent 领域知识与目录配置已进入试用开发版。
适用范围：目录树新建、已有目录配置、多选整理、归档导入及内置 Agent 的能力衔接。

> 本文整合原资源创建向导草案与手动组织流程调研。手动交互建议仍未实施；2026-10-01 按用户授权先补齐 Agent，后续已有用户对创建、配置与归组的试用，最新整理意图识别与完整验收仍待补充。正式事实及验证范围见 [内部文件操作](../agent-internal-file-actions.md#内置类型与归档组织)。本次状态核对未新增实机或真实 provider 验证，按 `docs/wip/README.md` 管理。

## 1. 结论与投入顺序

手动组织的主要成本来自操作拆分：用户想创建或整理一个漫画作品、视频合集、音频歌曲目录或 ASMR 归档，却要分别创建目录、设置内置类型、开启归档、上传内容和配置子目录。

建议围绕同一个“资源配置”表单，覆盖新建、已有目录和多选三个入口。界面用“类型 + 形态”表达目的，执行层仍沿用 `builtInType + archiveMode`，不新增一套资源身份模型。

| 顺序 | 建议改动 | 解决的问题 | 实施范围 |
| --- | --- | --- | --- |
| 1 | 已有目录“设置资源类型…” | 两次右键才能完成一种配置 | 合并两字段，复用单节点更新接口 |
| 2 | “新建资源…” | 先建普通目录，再补配置 | 复用表单，完成创建、配置和定位 |
| 3 | 多选“批量设置资源类型…” | Shift/Cmd 已能选中，却无法统一配置 | 目标快照、范围预览、批量执行与结果反馈 |
| 4 | 归档拖入后接续上传 | 被拒后还要重新找右键上传 | 调整现有拖拽约束，复用上传确认与上传中心 |
| 5 | 文件夹导入和结构计划 | 导入后还要逐个组织作品目录 | 按类型生成结构，支持失败项重试 |
| 6 | Agent 接入相同组织能力 | 已补配置闭环并有用户试用，最新意图识别与完整验收待补 | 领域 Skill、node.configure、library.batch 与提交回执已实现 |

第一批建议交付第 1、2 项；若独立迭代，先做第 1 项。多选、导入和 Agent 各自验收，不把全部能力压进首个弹框。普通“新建文件夹”的行内重命名操作保留。

## 2. 当前实现与操作成本

### 2.1 两个配置字段及其影响

- `builtInType`：`DEF / COMIC / ASMR / VIDEO / AUDIO / GALLERY`。
- `archiveMode`：`0 / 1`。归档是内置类型目录的附加形态。
- 配置影响目录图标、展开方式、双击打开目标、归档条目和拖拽规则，并非仅改变外观或标签。
- `builtInType / archiveMode` 与 viewer 分发用的 `fileType` 属于不同层次，不能混用。
- 产品约束要求 `DEF` 对应关闭归档；归档仅用于目录。现有前端设置回 `DEF` 时会同时关闭归档，开启归档前则要求先选择非默认类型。

正式语义见[内置类型与归档模式](../built-in-type-and-archive-mode.md)和[Viewer 映射](../file-viewer-and-archive-viewer-map.md)。

### 2.2 新建并填充一个归档

当前主路径：

1. 父目录右键“新建文件夹”，立即创建普通目录，再行内改名。
2. 新目录右键“内置类型”，进入子菜单选择类型。
3. 再次右键“归档模式”，进入子菜单开启。
4. 右键上传文件或文件夹，经系统选择器和上传确认进入上传队列。
5. 需要时，再对归档根执行“批量设置内置类型”。
6. 漫画、音频可能还要按名称排序，补充封面、歌词或字幕。

仅新建一个空归档就要三轮右键交互，包括两轮配置子菜单。创建和重命名之外，配置还被拆成两次请求。已有普通目录转归档也要两轮配置。

注意：“新建文件夹”当前不是弹框流程，`CreateNodeModal` 不能代表目录新建的实际入口。

### 2.3 已有资料整理的断点

| 断点 | 当前行为 | 用户后果 |
| --- | --- | --- |
| 配置顺序依赖 | `DEF` 目录仍能点击开启归档，随后提示先设置类型 | 一次可以避免的无效操作 |
| 多选与配置脱节 | 类型、归档动作使用右键单节点；多选未接入 | 一批目录要逐个处理 |
| 配置后折叠 | 非默认类型目录的类型或归档配置变更后会折叠，并清理原始目录展开许可 | 整理现场中断；非归档内置目录需重新“打开原始目录”，归档目录可再次展开 |
| 批量范围特殊 | 仅归档根可同步直属子目录的内置类型 | 不能代表任意选区或完整归档结构整理 |
| 新建不继承语义 | 普通新建目录默认为 `DEF + archiveMode=0` | 归档内新建作品仍须再配置 |
| 外部拖拽被拒 | 归档目录要求改用右键上传；内部节点移动可用 | 用户必须换入口重新开始 |
| 配置入口隐蔽 | 属性中的模式为只读，归档卡片菜单主要是重命名、定位、属性、删除 | 整理时常需返回目录树 |

现有“批量设置内置类型”只修改直属子目录的 `builtInType`，保留各子目录的 `archiveMode`，不处理直属文件或递归后代。其结果有目录数和更新数，没有通用组织计划、逐项冲突或撤销能力。

### 2.4 Agent 能力边界

当前专用资料库工具具备创建目录、移动、复制、重命名及 `node.configure`，可以同时更新目录的 `builtInType / archiveMode`，`library.batch` 可组合明确目标。`directory.create` 仍沿用普通目录创建接口，创建和配置是两次提交。

基础概念已进入系统提示词，详细结构通过 `resource-organization` 按需加载；同一 Run 可组合多个 Skill，依赖不裁剪工具，简单明确操作不强制加载。Shell、CLI 和插件仍按实际注册、权限及环境使用。手动路径应独立完成任务，不依赖模型可用性。

## 3. 推荐交互

### 3.1 共用表单，按入口裁剪字段

| 入口 | 默认目标 | 主要字段 | 提交结果 |
| --- | --- | --- | --- |
| 新建资源… | 当前右键目录；工具栏使用明确的当前目录 | 类型、形态、名称、位置 | 创建并配置一个新目录 |
| 设置资源类型… | 当前目标目录 | 类型、形态 | 更新该目录配置 |
| 批量设置资源类型… | 打开命令时冻结的选中目录 | 类型、形态、处理范围 | 更新预览中的明确目标集合 |

类型包括漫画、ASMR、视频、音频、图集；形态使用“作品 / 单元”和“合集 / 归档”，并按类型显示“漫画作品”“视频合集”等具体结果。普通目录提供明确的“恢复普通目录”动作，同时设置 `DEF + archiveMode=0`，不删除内容。

原来五类类型中的图集也应纳入配置表单，不能因早期创建草案未列出而遗漏。文件节点已有的类型入口另行保持兼容，本方案首批面向目录。

单目录配置使用一个紧凑表单，不强制经过多页向导。只有涉及子目录批量、移动或文件夹拆分时才展开计划列表；简单配置在提交按钮前显示简短结果摘要即可。

### 3.2 三条目标路径

**已有目录转漫画归档：**

目录右键“设置资源类型…” → 选择“漫画 / 合集” → 应用。一次更新同时提交类型和归档模式。已有内容不移动、不改名；子目录整理是独立可选范围。

**新建 ASMR 作品：**

父目录“新建资源…” → 选择“ASMR / 作品”、输入名称 → 创建。成功后定位新目录，提供打开资源、打开原始目录、上传内容入口；连续整理时默认保留目录现场，不强制跳走。

**批量整理漫画卷目录：**

Shift/Cmd 选中目录 → “批量设置资源类型…” → 选择“漫画 / 作品” → 预览目标与跳过项 → 应用。已有子归档或其他类型需要显式列出，不能混在普通作品中静默重置。

### 3.3 位置与弹框密度

- 默认沿用当前目录，展示 `/` 开头的资料库逻辑路径；更改位置复用现有目录选择能力。
- 复用 `CompactModal` 或现有目录树 overlay 的紧凑外观、主题和焦点规则，不重新复制 Semi 默认大留白。
- 类型用现有图标体系和短名称，不做大卡片套卡片，也不把技术字段写进普通用户说明。
- 根据真实内容确定宽度并设置视口上限，不沿用早期草案“720px 起步”的固定建议。
- 目录选择区保持稳定高度，空目录也不塌陷；预览列表在受限区域滚动，标题和底部按钮保持紧凑。
- 少字段配置不必重复确认；批量的“应用”本身就是用户对所见计划的确认。

## 4. 子项整理、上传与类型模板

### 4.1 子目录策略应有明确范围

将原“批量设置内置类型”逐步接入同一配置入口，按用户目的显示“将直属子目录设为漫画作品”等名称。建议提供：

- 不处理子目录：单目录设置的默认值。
- 仅处理未配置的直属目录：批量整理时推荐，保留已有非默认类型和子归档。
- 指定直属目录：用户预览并勾选后执行。

首批不做递归传播。预览应列出根目录与子目录分别怎样变化、已匹配项、跳过文件、已有子归档及冲突。数字必须来自目标范围的实际查询，不能只统计目录树当前加载的节点；不读取无关文件正文或拉取整个资料库。

多选快照按节点 ID 去重。父子同时选中时避免重复写入；如同时启用子目录策略，冲突策略先明确再执行。跨库目标拒绝，混合文件选择明确跳过文件。

### 4.2 各类型不能套用同一套层级规则

| 类型 | 作品 / 单元的推荐内容 | 归档中的当前主要展示规则 | 导入建议 |
| --- | --- | --- | --- |
| 漫画 | 图片页 | 直属漫画作品；漫画子归档可作合集卡片 | 一卷一个作品目录，嵌套合集明确选择 |
| 视频 | 主视频、封面、字幕 | 直属视频单元及子合集；兼容直属视频文件 | 长期优先每集一个单元目录，保留裸视频兼容 |
| 音频 | 主音频、封面、歌词 | 直属歌曲目录及裸音频；下级音频归档不作为上级合集条目 | 不默认生成嵌套音频归档 |
| ASMR | 多音轨、封面、说明 | 按 ASMR 作品规则展示；不能默认套用漫画嵌套行为 | 一个作品目录保留多音轨，避免逐音轨拆作品 |
| 图集 | 图片、视频 | 直属图集目录及下级图集归档 | 每组一个图集目录，不递归铺平 |

上述是组织建议和当前展示约束，不要求改写现有用户目录。实现导入前仍须核对对应 viewer 与后端卡片查询；图集使用自己的查询链路，不能假定所有类型都走同一个归档卡片接口。

例如漫画导入计划应展示用户可读的结构：

```text
某系列 / 漫画合集
  第 01 卷 / 漫画作品
  第 02 卷 / 漫画作品
```

图片页自然排序、封面、字幕和歌词匹配作为后续显式选项。文件扩展名识别可以用于建议，不能直接决定多音轨如何拆分或覆盖用户已有配置。

### 4.3 上传连续性

当前归档拒绝外部拖拽是已有明确约束，解除时应同步修改目标解析、上传、测试与专题说明。目标体验是拖入后直接进入现有上传确认，携带当前目录及实际文件候选，不要求用户重新选择同一批文件。

上传确认继续保留必要的存储目标和健康检查。只创建目录时不出现存储桶字段。可以使用已有默认选择减少操作，但不能为省一步跳过真实上传校验。

向导复用上传中心的进度、并发、取消和重试。导入到归档时，对“将新建直属目录设为同类型作品”展示可取消的选择；不把父类型默默传播给所有普通目录、文件或后代。

## 5. 技术落点与一致性

### 5.1 单目录配置

`updateNodeConfig` 已支持一次 `PUT /v1/nodes/:id` 同时发送 `builtInType` 和 `archiveMode`。合并现有目录的两个菜单操作不需要先发明资源编排 API。

服务端应统一校验字段枚举、目录适用范围及 `DEF` 与归档模式的组合，不只依赖 UI 的先后顺序。已有历史合法文件配置须保持兼容，不能把目录向导的范围限制直接扩大为所有节点的新规则。

### 5.2 新建不是单次原子操作

现有 `createNode` 参数没有这两个配置字段。复用现有接口意味着“创建目录 → 配置目录”两个提交阶段；单次配置请求的原子性不能推导成整个创建流程原子。

首批可采用前端编排，但必须保留已创建节点 ID 并在配置失败后重试同一节点。创建响应超时且结果未知时，先核对提交结果，不能直接再次创建；缺少可靠核对契约时应显示待确认状态。

后续优先评估扩展既有创建契约，让合法配置在目录创建事务内初始化。只有真正需要多目录计划与恢复时，再评估独立资源编排接口；本文不预设新的路由或数据表。

### 5.3 通用批量配置

现有 `PATCH /v1/nodes/:id/archive/built-in-type/batch-set` 不支持任意选择集、形态更新或完整计划预览，不能直接换个按钮名宣称完成批量组织。

建议为配置批量提供明确目标、预览结果和提交回执。单批采用事务时，全成功或全失败；超出单批限制分段执行时，则明确各段已提交、失败及未执行范围。不能同时声称整体原子又返回模糊的部分成功。

预览到执行之间，应重新校验节点是否存在、归属、类型及适用的版本信息，防止过期计划覆盖其他操作。具体批量上限、条件更新字段及事务设计在开发时确定。

### 5.4 复用既有状态归属

- 资源配置 feature 持有表单草稿和执行计划，不持有第二份目录树。
- 树结构通过 `useRepositoryTree` 和现有 mutation / refresh 链路更新，选择继续由 `DirectoryTree` 持有。
- 打开资源走现有打开链路和 `FileViewerContext`，不根据按钮文案另造 viewer 分发。
- 上传事实归上传中心；向导只关联目标目录与任务，不维护另一套上传状态机。
- 保留仍有效的选区、滚动位置及原始目录浏览上下文；如产品决定继续自动折叠，应提供直接返回原始目录的动作，不靠强制折叠解决刷新问题。
- 批量后刷新受影响子树及已打开归档的派生数据，不只修改当前可见子节点图标。

## 6. 失败、取消与恢复

| 情况 | 对用户的反馈与恢复要求 |
| --- | --- |
| 创建前失败 | 保留表单草稿，未创建目录 |
| 创建已成功、配置失败 | 告知目录已创建，允许对同一节点补配，不重复创建 |
| 配置已成功、刷新失败 | 告知配置已保存但视图待刷新，不重放写入 |
| 上传部分失败 | 保留目录和成功内容，沿用上传中心重试失败项 |
| 用户取消 | 停止未执行阶段，结算在途请求；不把已提交内容当成未发生 |
| 请求超时、提交结果未知 | 查询或核对原操作结果，核对前不直接重复执行 |
| 预览后目标改变 | 显示冲突并重新预览，不静默覆盖 |

撤销可以作为后续能力，但必须保存原配置并在恢复时检测后续变更。没有实现和验证前不展示“可撤销”承诺；配置撤销也不代表上传、移动或整个导入自动回滚。

## 7. Agent 衔接与本轮非目标

手动表单和 Agent 应复用相同的配置规则、范围校验及结果语义，保持独立入口。

`node.configure` 已接入现有 Registry / Broker、目录访问与审批、提交三态及 UI 同步。`resource.create`、`archive.organize` 仍只是后续候选，不是当前 Tool。先用现有创建、配置、移动和批量动作完成目标；流程建议不强制固定顺序或逐步确认，批准由现有权限模型决定。

首批不包含：

- 自动猜测整个资料库的类型或递归批量改写。
- 自动移动、拆分已有内容或把全部作品改成子归档。
- ZIP / CBZ 自动解包、复杂剧集识别、自动抓封面、字幕与标签生成。
- 重写播放器、漫画阅读器或视频选集栏。
- 新造上传中心、通用工作流引擎或以 Agent 为手动入口的必备依赖。

漫画嵌套等既有展示能力按当前事实使用，不再把早期草案中的相关 viewer 改造作为简单资源配置的前置条件。

## 8. 分阶段验收

| 阶段 | 最小完成范围 | 关键验收 |
| --- | --- | --- |
| A：配置已有目录 | 五类类型、作品/归档、恢复普通目录、单次更新 | 普通目录一次设成漫画归档；关闭归档与恢复默认均合法；失败保留草稿 |
| B：创建资源 | 名称、当前位置、创建+配置、定位及后续入口 | 无需再右键补配；配置失败可重试同一目录；未知结果不重复创建 |
| C：多选整理 | 选区快照、预览、子项策略、批量回执 | 5 个目录一次配置；覆盖混合文件、父子重叠、已有子归档、跨库、冲突和部分执行 |
| D：导入闭环 | 拖入接续上传、多文件夹结构计划、任务关联 | 漫画多卷、ASMR 多音轨、视频字幕、音频歌词均按预览组织；失败可核对和重试 |
| E：Agent 接入 | 专用配置/组织工具与结果展示 | 同一目标与手动入口结果一致；拒绝、取消、超时、离库和刷新失败语义正确 |

交互验证还应覆盖长路径、大目录分页、空目录、亮暗主题、100% 页面缩放、键盘焦点和窄窗口；新界面不能重新引入过宽内边距、过高标题/footer 或目录选择区塌陷。

实施时按前端规范执行 lint、测试、构建及对应手工矩阵；涉及后端则遵守后端规范。任何真实资料库验证都禁止使用第一个资料库，优先可用的 Win，且遵守本机 macOS MinIO 的环境限制。

本手动方案尚未实施，上述手动交互用例未验证。原调研阶段仅更新文档，未执行构建、自动测试或资料库写操作；后续 Agent 实施与验证记录以正式专题为准，本次状态核对不新增实机验收结论。

## 9. 待落地时确定的产品选择

| 问题 | 本次建议 |
| --- | --- |
| 新建后是否自动打开 viewer？ | 默认定位并保留整理现场，提供显式打开动作 |
| 改归档时是否自动处理子目录？ | 默认不处理；批量整理推荐仅未配置的直属目录 |
| 视频/音频裸文件是否默认包一层目录？ | 保留现有结构；导入时可选择每作品一个目录，预览后执行 |
| 何时扩展后端创建接口？ | 可先验证简单交互；若前端编排无法可靠核对与重试，就先补创建契约 |
| 是否首批提供快捷键和归档卡片整理工具？ | 后置；先收口目录树与共享配置表单，后续复用同一命令 |
| 是否首批提供一键撤销？ | 不作为低成本承诺；有前态、冲突检查和恢复验证后再开放 |

这些是建议默认值，尚未转化为实施决定。
