# Agent 模型预算与体验边界

更新时间：2026-10-23

## 1. 模型预算

当前预算解析使用随应用发布的 Codex CLI `d6817454d76885e9d0e118bbf82e507aed6f715a` 窗口快照 `src/shared/ai-model-catalog.json`：复制精确模型 ID、默认窗口、最大可配置窗口及单 Agent 推理档位，不在运行时读取 Codex 仓库或用户 Codex 配置。窗口数据与 `agent-model-profiles.ts` 的执行适配分离；模型提示词与工具协议的实际适配见 [模型执行适配](agent-model-adaptation.md)。常规聊天由 main 自动解析预算，用户选择模型和推理强度。

OmniFlow 的解析顺序：

1. 从当前配置连接的 `/models` 读取模型身份和可选扩展元数据，支持 `data / models` 集合、`id / slug / name`、`context_window / context_length`、`max_context_window`、`max_output_tokens` 与 `top_provider.max_completion_tokens`。仅含 ID 的合法条目也保留；通用 OpenAI `/v1/models` 并不承诺这些窗口字段。
2. 只有服务档案选择 OpenAI（`providerType=openai`）、该连接目录确实列出当前 ID、该 ID 精确命中内置快照，才采用快照默认窗口。仅去除 ID 两端空白，不把大小写、日期后缀或自定义别名猜成同一模型。未满足条件时仍可调用模型，窗口使用远端 `context_window`、其次 `max_context_window`，再回退默认预算；不把目录缺失变成执行禁用。工具与推理适配原有日期规则不受窗口精确匹配影响。
3. 目录和元数据都未提供窗口时使用 `128,000` 上下文；输出预留仍优先使用合法远端输出限额，没有该限额时才回退 `4,096`。这是 2026-09-12 起的兼容默认预算，不是模型真实容量保证，也不能称已验证安全下限。UI 显式标注来源。缺少信息时应完善供应商元数据或维护目录，不要求用户在聊天中填写 token 数值。

目录数值是客户端默认值，不等于供应商当前模型规格。本轮复制固定 Codex 快照的 11 个条目：`gpt-6.1-sol` 默认 `272,000`、最大可配置 `872,000`；`gpt-6-astra` 的旧 1.05M 值改为快照的 272k / 872k，新增 `gpt-6-sol` 和 `gpt-6-luna`。不在该快照中的旧型号走远端窗口 / 默认预算，不能沿用另一份过期窗口表。目录最大值是配置上限，远端较大的最大值不能扩大它；默认请求与 UI 分母不自动使用最大值。旧 Run 保留旧分母，新 Run 才用新目录。

现行 catalog 优先会忽略同名兼容网关报告的更小窗口；这是尚待区分“模型窗口 / 路由请求上限”的已知限制，不意味着代理一定支持目录窗口。后续应新增有来源的独立输入 cap 并取交集，不把模型名作为能力证明，也不能直接采用两个上游目录中较大的值。Codex 与 OpenCode 同名模型目录差异及推荐路线见 [研究文档](agent-context-compaction-research.md)。

成功目录快照由 AI 服务层 `aiServiceModelDiscoveryCache` 统一持有，模型菜单成功读取 `/models` 后也发布到该缓存，Agent 可直接复用，避免已选中的模型因另一次独立发现失败而被当作未知。缓存按 Provider、Base URL 和凭据的不可逆摘要隔离，最多保留 32 个连接、5 分钟新鲜度；仅保留模型 ID 与白名单元数据。请求序号防止晚到旧响应覆盖较新的成功目录；合法空目录可以清除旧身份，畸形响应和失败不覆盖成功快照。

Agent wrapper 仍合并同连接并发请求、限制发现请求 3 秒并在失败后冷却 30 秒；同连接已有成功缓存时可继续沿用缓存身份，无缓存且失败时不套用 Codex 表。模型菜单普通读取优先复用五分钟内成功目录，并合并同连接在途请求；过期后重新读取，最多等待十秒。`listModels({ forceRefresh: true })` 跳过缓存并报告真实失败，不能把 Agent 的静默回退套到显式刷新动作。没有将凭据、完整上游响应或新执行能力暴露到 renderer。

Composer 不提供预算编辑按钮或弹层，相关 `agent:model:budget` IPC 和 preload 方法已移除。`agent:chat:start` 不再声明或消费 `modelBudget`；旧客户端即使发送该遗留字段，main 也只按当前连接的元数据和模型目录自动解析，不接受隐藏的 renderer 覆盖。每个 Run 在启动前解析并冻结预算，之后沿用原有压缩与 usage 低估补偿机制。

读取模型偏好时只清理已退役的 `agent-model-budget:v1:*` 键，保留模型、推理强度和其他应用设置。即使本地存储不可清理，旧值也没有生效路径。底层 resolver 保留有界配置注入和校验能力，供内部测试或后续供应商高级配置接入；当前没有面向用户的高级预算配置入口。

有效请求窗口保留 5% 余量，输出上限自动遵循服务端限制、本地最多 `16,000` tokens 和不超过窗口四分之一的预留策略；可见文本另受每 turn / Run 的 `64,000` 字符保护。更大的模型理论输出能力不等于客户端已经允许无限累积文本。main-owned ledger 和 Run 快照继续记录服务端基准、增量估算及安全可追加空间，不把累计 usage 当作窗口占用；Composer 用圆环与单个百分比展示快照，详情见 [上下文计量](agent-context-accounting.md)。

### 最大可配置窗口的含义与后续入口

Codex 的 `model_context_window=872000` 覆盖默认窗口，再受模型 `max_context_window` 截顶；HTTP / WebSocket Responses 请求不携带 `context_window` 参数。它改变客户端保留历史和触发压缩的时机，不会向代理申请或解锁额外容量。按其默认规则，872k 对应 828,400 可用窗口、784,800 自动压缩阈值；这些数字不能直接替代 OmniFlow 当前的输出预留与低估校正公式。

OmniFlow 后续若开放长上下文，应放在现有 AI 服务档案的模型配置内，按精确模型 ID 保存“自动 / 长上下文”或有界自定义值；只在该模型最大值高于默认值时提供扩展选项。main 保存校验，在创建下一 Run 时冻结，当前 Run 与历史分母不变。以 872k、16k 输出预留、95% 有效比例为例，当前公式的输入上限为 813,200，之后仍扣实测低估校正及工具预留。不能通过改百分比分母而不改实际调度来实现，也不恢复已退役的 Composer `modelBudget` 存储。本轮没有启用 872k 或新增配置入口。

### 缓存友好的提示词前缀

稳定策略、工具路由、模型适配和 Skill 目录放在前面；目录 ID、选区及本轮感知说明放在末尾。当前事实仍完整发送，不冻结旧选区来追求缓存。保留工具定义顺序、原消息和推理配置，不额外设置缓存 TTL 或网关未知参数；是否命中及实际节省由服务端决定。

当前 Run 摘要复用工作请求前缀仍是待对照方案：需要真实前缀快照、完整预算、禁用工具的协议和运行时拒绝，以及独立消费计量。保留更多历史、工具定义和原推理强度可能增加摘要成本；跨 Run 缺少精确 Provider 请求前缀时不能宣称可直接复用。因此本轮只优化提示词排列，不更换摘要算法。

## 2. 流式可靠性

- OpenAI-compatible 必须有合法 `finish_reason`；Claude 必须同时取得合法 `stop_reason` 与 `message_stop`。单纯 EOF 不代表成功。
- `length / max_tokens`、内容过滤、异常结束或不完整响应明确失败并保留已显示内容，不将半截回答或工具参数当作完成。
- 未声明 Tool 的兼容请求也走相同的校验链路，省略 `tools` 字段，不能通过纯文本 fallback 绕过校验。
- 120 秒无响应活动触发空闲超时。读取到终止标记后释放流，不继续等待网关关闭连接。
- 对网络错误、408 / 429 / 500 / 502 / 503 / 504、空闲超时和不完整流，只有本次尚未向用户显示文本时才至多重试两次；等待退避可取消。不自动重放 Tool、已显示的回答、上下文超限或输出超限。
- 历史摘要仍是独立的无 Tool 调用；摘要失败沿用原有有界回退，不影响规范 ToolRun 事实。

## 3. 感知与界面

- 目录感知最多保留 200 项，但 `entryCount` 保留规范化后的总数，`truncated` 明确标识不完整；main 再次规范化时保留此信息。
- `file.list` 返回总数、实际返回数和截断标记，不能以部分结果断言未展示文件不存在。当前仍不支持自主递归浏览和目录续页 Tool，不能把本次修复写成全库检索能力。
- 失败、取消和中断 Run 在时间线保留规范终态行；即使 Provider 在首个文字输出前失败，重开会话后仍显示原因。空 streaming item 显示“正在思考”，不创建假消息或另一套 Run 状态。
- Composer 支持运行中起草；IME composition 与兼容 keyCode 229 的回车不提交，Shift+Enter 保持换行。停止点击必须阻止表单默认动作，避免快速终态把同次点击变成草稿提交；停止失败显示错误并保留现场。任务仍在运行时不发送新草稿，不提供自动排队或运行中插入指令。
- 最终回答使用 `react-markdown + remark-gfm` 展示标题、列表、表格和代码；禁用 HTML、MDX、外部媒体加载和模型链接导航。链接只保留文本，图片只保留 alt，代码和完整回答可复制。过程说明仍为纯文本。
- 当前不增加模型生成的可执行 UI、本地路径打开、产物预览或任意导航入口。持续进程会话、工具并行、运行中插入指令、附件与受控产物打开需独立升级协议。
