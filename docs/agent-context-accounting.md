# Agent 上下文计量

更新时间：2026-10-23

## 计量边界

上下文计量由 Electron main 的 Run 内 ledger 持有，renderer 只展示 Run 快照，不自行数聊天文字或累加 usage。它借鉴 Codex 的“服务端基准 + 新增条目估算”，但当前 Agent 使用既有 OpenAI Chat Completions / Claude Messages 消息历史，不照搬 Responses 的加密 reasoning 记账或 TUI 固定 12,000-token 基线。

三个不同数字：

- 当前估算输入：下一次保留的消息、工具调用与结果、系统提示词、工具定义所占空间。
- 安全可追加空间：扣除输出、安全系数、保守校正和工具预留后的空间，不等于标称窗口减聊天文字。
- 本 Run 已报告累计用量：成功响应提供的 total，或完整 input+output 的累计；不用于扣减上下文窗口，不包含辅助摘要、未报告的失败和重试，也不是费用金额。

## 服务端基准与增量

每次完成模型响应后，若存在合法 inputTokens，则记录该请求的服务端输入、请求本地估算、系统及工具定义指纹、消息前缀指纹。只保存 hash，不为计量复制整份历史。

当前请求保留相同固定内容与相同消息前缀时：

```text
当前估算输入 = 最近实测输入 + 当前本地估算与基准本地估算的增量
```

可见回答和工具调用参数作为新的 assistant 条目计入增量；不把 completion_tokens 全部当作下次输入，因为它可能包含不再回传的隐藏 reasoning。cachedInputTokens 仍占上下文，不从占用中减掉。

工具定义、系统提示词、消息前缀变化，或历史被压缩后，旧基准不再适用，回到当前完整请求的本地估算；下一次有效 usage 重新建立基准。不同 Run / 模型独立建立 ledger，不把旧模型的占用当作新模型实测值。

本地估算沿用当前启发式：非 ASCII 字符约 1.1 tokens，其他字符约 1/3.5 token，并包含消息和工具协议开销。它不是精确 tokenizer；估算来源明确区分 estimate、provider、provider-plus-estimate。

## 调度与安全预算

```text
输入上限 = floor((模型窗口 - 回答预留) * 有效比例)
校正量 = 本 Run 各次 max(服务端输入 - 当次本地估算, 0) 的最大值
安全输入计数 = max(当前基准增量估算, 当前本地估算 + 校正量)
安全可追加 = max(0, 输入上限 - 安全输入计数 - 工具预留)
```

现有调度、压缩和 Tool 结果预算统一从 ledger 获取扣除校正量后的请求上限；显示也使用同一校正量和预算，不引入另一份 renderer 状态。服务端比本地估算低时，当前占用可以显示更准确的基准增量值，但不会因此突破原来的保守调度上限。压缩后保留该 Run 已观测的低估校正，避免忘掉供应商隐藏开销。

辅助摘要也遵守输入有效比例和当前模型输出预留。跨 Run 每批包含system prompt、前一摘要及完整JSON协议开销，超限缩减完整片段，不能容纳时沿用旧的有界历史回退，不推进checkpoint；最多四批的规划与执行共用预算。当前 Run 摘要的候选与发送共用有效输入上限，并复用同一ledger低估校正；摘要输出最多2,048，跨Run最多4,096，均不能超过本模型输出预留。辅助摘要的完整usage/cost尚未纳入Run累计统计。

整理计数记录历史精简及当前 Run 成功压缩事件，不是累计 token 消耗。实际触发继续使用原有有界压缩机制；本轮没有把策略改成固定到 90% 就压缩。

Active Context 现在在超预算时先尝试[旧正文清理](agent-context-pruning.md)。成功提交也通过同一 onCompacted 回调使计量基准失效并增加整理计数；暂存清理及失败回滚不改变用量事实，不计算成一次模型调用。

## 缺失与持久化

- usage 字段必须为非负安全整数；缺失、null、布尔值及数字字符串不当作实测 0。
- 只有输出或 total 时，不伪造输入基准。可以继续用先前仍适用的基准，否则只做本地估算；累计报告缺失时标记不完整。
- 输入等待或流式生成期间显示最近的请求快照，不声称包含未完成响应；未发送草稿不在其中。
- `agent_runs.context_usage_json` 保存白名单数字与状态，Run 更新递增同一 revision，通过既有 run-updated / 会话恢复链投影。没有新增 IPC 通道。
- SQLite 通过原有 RUN_RUNTIME_COLUMNS 初始化迁移幂等补齐 nullable TEXT 列，Schema Coordinator 同步验证该列；保持兼容的 schema 2，不涉及 PostgreSQL 或 Go model 生成。
- 终态保留最后快照。旧 Run 没有统计时显示未知，损坏的可选统计不会阻断整个历史会话恢复；切换模型或服务配置时不把旧快照当作当前统计。

## 界面

Composer 在模型选择器左侧显示静态小圆环和单个百分比，复用 main `Run.contextUsage`；不数 renderer 聊天正文、不建立新存储或 IPC。比例为 `estimatedInputTokens / windowTokens`，即保留请求上下文占本次 Run 所用窗口预算的比例，不扣隐藏的固定基线，也不使用累计消费或安全可追加量作为分子。普通值向下取整；非零但不足 1% 显示 `<1%`，超出窗口显示 `>100%`，图环最多填满。圆环没有加载动画，不能被理解为任务进度。

悬停和无障碍描述注明这是约数，展示 token 分子/分母、实测或估算来源、窗口来源、安全可追加空间与回答/工具预留。内置目录是客户端默认预算；fallback 明确写“默认预算，模型实际上限未知”。这个比例不是达到 100% 才压缩的开关，调度仍遵守上述安全预算。

内置窗口来自随包发布的 Codex 静态表，仅服务档案选择 OpenAI、当前连接 `/models` 列出同一 ID 且精确命中表时使用；普通 ID-only 列表也能匹配。未命中时用 Provider 元数据或默认预算，不用别名推断。最大可配置值不是当前比例分母；来源门槛与扩展窗口含义见[模型预算](agent-model-context-and-reliability.md)。

只选当前 Session 最新 Run，按模型、请求推理强度（`requestedReasoningEffort ?? reasoningEffort`）、服务档案 ID 匹配；档案更新时间晚于 Run 创建时间时失效旧测量。main 将不支持的请求档位归自动时仍可展示该请求的真实快照；用户实际切档后则失效，不能借此复活旧快照。开始新 Run、配置加载、会话恢复期间先显示未知 `—`；最新 Run 没有统计时不回退更早 Run。切换模型/档案、旧历史缺统计、损坏统计或窗口为零均不伪装成 0%。空闲时标为“上次运行快照”，草稿和未完成流式输出不计入。更新内置目录不会重算已保存历史快照的分母，新 Run 才解析新预算。

最新源码与后续压缩升级的比较见 [上下文与压缩研究](agent-context-compaction-research.md)。下方 2026-09-08 记录是旧统计行阶段的历史验证；本次圆环的验收以验证矩阵 2026-10-23 条目为准。

## 验证

自动化覆盖服务端基准、追加消息、工具结果、缓存输入不扣除、隐藏 reasoning 不重复计入、压缩/内容/工具变化失效、未知 usage、保守上限、Run 计数持久化、关闭后重开、owner 隔离、历史未知显示，以及主进程真实分发到 SQLite/renderer。

真实 gpt-5.5 在非第一个 win 资料库完成隔离三行文本续读：4 次响应，最近输入 11,629，计入可见回答后的上下文估算 11,696，本 Run 已报告累计 45,822，安全可追加 225,003；窗口使用内置目录默认 272,000。实际缓存输入 10,752 未从上下文扣除。暗色桌面界面数字与 SQLite 一致、无重叠。该数值只代表这次验收，不是固定模型开销。

最终检查：1,968 项测试通过、7 项跳过，lint、TypeScript、完整构建及源码 diff 检查通过。开发进程重启后，新会话显示暂无统计，恢复原会话后仍显示同一份用量快照。真实界面已覆盖暗色桌面与会话恢复；全部主题 / 窗口尺寸、真实长上下文压缩与供应商 usage 缺失等复杂场景尚未逐项人工验收，后者由自动化覆盖。本轮未修改后端或读取真实用户文档。
