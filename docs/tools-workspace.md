# Tools Workspace 说明

更新时间：2026-08-23

适用范围：`src/views/library/detail/` 中的 `tools` 工作区模式，以及 `src/features/tool-workspace/` 下的工具域能力。

## 1. 概述

`tools workspace` 不是单独的路由应用，而是 `library detail` 页面里的一个工作区模式。

当前目标：

- 保留目录树上下文。
- 让复杂工具流程从设置页和内容页中抽离出来。
- 支持后续从视频、音频、文件详情等位置带上下文进入工具区。

当前工具包括：

- `AI 服务配置`
- `QQ 音乐歌词`
- `AI 字幕翻译`
- `媒体文件处理`
- `资源捕获处理`

## 2. 工作区层级

当前 `library detail` 的 `workspaceDisplayMode` 有 4 种：

- `search-home`
- `file-viewer`
- `browser`
- `tools`

其中：

- 页面层继续拥有“当前显示哪种工作区模式”的 owner。
- 工具自身的业务状态不回写到页面层，而是收敛在 `src/features/tool-workspace/`。

当前结论：

- 页面层只负责进入 / 离开 `tools`。
- 工具区内部具体是哪个工具、字幕当前草稿是什么，属于工具域自己的状态。

## 3. 当前工具区结构

当前 `tools workspace` 的结构分为两层：

1. 页面层容器
   - 位于 `src/views/library/detail/index.tsx`
   - 负责：
     - 工具区入口按钮
     - 切换 `workspaceDisplayMode='tools'`
     - 保留目录树显示
     - 将目录树当前选中节点透传给工具区
     - 从浏览器资源面板把已选媒体资源送入媒体处理工具

2. 工具域实现
   - 位于 `src/features/tool-workspace/`
   - 负责：
     - 工具导航壳
     - 工具导航默认宽度为 `208px`，可在 `57px～240px` 内调整；菜单卡片在展开和纯图标形态下统一保持 `32px` 高，工具图标始终锁定在左侧 `28px` 中心线上；纯图标态保留 `32px` 视觉框，但点击热区透明扩展到约 `40px × 38px`。默认显示排序手柄，中间宽度单行省略名称，最窄状态只显示图标并在悬停时提示工具全称
     - 分割线左侧顶部的双箭头用于快速收起 / 展开导航；导航宽度、按钮位置和双箭头旋转使用同步动效，收起后导航进入与手动拖到 `57px` 相同的纯图标形态，再次点击恢复收起前的自定义宽度
     - 宽度达到 `180px` 后，每个工具末尾显示排序手柄；拖拽结束后按稳定工具 ID 保存新顺序
     - AI 服务档案管理
     - QQMusicMac 本地曲库检索、QRC 逐字预览和库内保存
     - 字幕翻译配置
     - 字幕解析、翻译、另存为
     - 内部媒体文件处理：从目录树右键进入，提取音频、压缩画质
     - 浏览器捕获媒体资源承接、音视频合并、转格式
     - HLS 下载计划承接与执行
     - 工具草稿缓存

## 4. 目录树联动

当前工具区没有新造一套“库内文件选择器”，而是复用目录树当前选中节点。

目录树当前透传字段包括：

- `primaryNode`
- `selectedNodeIds`
- `rootNodeId`

用途：

- 导入库内字幕时，读取当前选中的字幕文件。
- 另存为到库内时，优先使用当前选中目录作为目标目录。

当前保存目标回退规则：

1. 当前选中目录
2. 当前选中文件的父目录
3. 源字幕文件的父目录
4. 当前库根目录

媒体处理工具不再直接展开全部目录下拉；改为“保存到本地 / 保存到内部”单按钮切换（与搜索主页模式切换风格一致，含背景色与图标状态变化）。

## 5. AI 服务配置工具

`AI 服务配置` 是本机 AI provider 档案入口，当前支持：

- 新增、编辑、复制、启用和删除服务档案。
- 服务类型支持 `DeepSeek`、`OpenAI`、`Claude` 和 `Local`，选择器使用对应服务商图标。
- 保存配置名称、Base URL、服务类型和可选 API Key。
- 第一条配置自动启用；删除当前配置后按列表顺序启用下一条，列表为空时回到未启用状态。
- 列表占满工作区可用宽度，可拖动左侧 provider 图标上下排序；顺序保存在本机 AI 服务配置文件中。

当前它只管理 provider 连接，不管理具体模型、推理强度、翻译目标、提示词等任务配置。`AI 字幕翻译` 已通过受控 API 使用当前启用档案，但具体任务参数仍由字幕工具持有。档案数据仅保存在 Electron `userData/ai-services.json`，不会同步到后端。API Key 由 Electron `safeStorage` 加密；renderer 列表只接收 `hasApiKey`，进入已有档案编辑页时立即单次读取指定 Key，并以真实 password value 显示长度一致的掩码，眼睛只切换显示和隐藏。修改后保存会覆盖，清空后保存会删除，取消或保存后明文草稿立即丢弃。

详细边界和 IPC 契约见 `docs/ai-service-architecture.md`。

## 6. AI 字幕翻译工具

### 6.1 当前能力

- 读取本地字幕文件
- 将单个本地 `.srt / .vtt` 文件拖入整个字幕工作区后直接读取
- 读取库内字幕文件
- 自动解析 `srt / vtt`
- 列表展示：
  - 时间戳
  - 原文
  - 译文
- 单句翻译
- 一键翻译全部
- 译文手动编辑
- 另存到本地
- 另存到库内文件系统

### 6.2 模型协议

字幕工具通过当前启用的 `AI 服务配置` 请求模型，不再单独填写 Base URL 或 API Key。模型列表路径统一使用当前服务的 `Base URL + /models`，具体鉴权与补全协议由主进程按 provider 适配：

- `OpenAI / DeepSeek / Local`：Bearer 鉴权，补全使用 `/chat/completions`
- `Claude`：`x-api-key + anthropic-version`，补全使用 `/messages`

字幕页不再使用顶部模型配置表单。读取本地字幕、读取选中文件、合并重复行、本地另存和库内另存统一为标题右侧的图标工具栏；当前文件名位于底部左侧。字幕列表弹性占用主要空间，底部固定显示聊天输入栏式翻译控制区：

- 本地拖入只接管标准 `DataTransfer.files`，不识别网页 URL、HTML、目录树内部拖拽或上传候选；一次只能读取一个不超过 `20 MB` 的 `.srt / .vtt` 文件。renderer 直接通过标准 `File.text()` 读取用户明确拖入的内容并复用现有字幕解析器，不新增本地路径 IPC，也不进入上传中心。拖入文件成功解析后才停止旧翻译并替换草稿；多文件、超限文件、错误扩展名或无效字幕不改变当前草稿。

- 提示词直接在主输入区编辑，并独立负责目标语言、术语、语气和专有名词等全部翻译要求。字幕配置不再单独保存或向请求拼接目标语言，旧偏好中的 `targetLanguage` 字段会在读取时忽略并清理，避免固定目标语言覆盖提示词。
- 右侧模型设置一级菜单展示模型、推理强度和上下文窗口的当前值。模型和推理强度分别使用独立的 Semi Popover，以当前行的真实 DOM 为锚点，并复用目录树菜单的视口空余空间计算；左侧和下方空间足够时用 `leftTop` 让二级栏顶边与触发行对齐，下方不足时改用 `leftBottom` 向上展开，左侧不足时再切换到右侧。不同二级栏必须按自身实际或最大尺寸参与选位，Semi 继续负责最终边缘修正；禁止把两栏放进同一个会随内容变高的浮层后手算偏移。模型二级栏首次展开时才自动读取当前启用服务的模型列表，同一次字幕页面停留只成功读取一次，失败后允许下次展开重试；这里不再提供模型文本输入或手动刷新按钮。上下文窗口不打开二级栏，在一级菜单原位置点击数字直接编辑，并隐藏数字步进按钮。
- 读取到的模型按版本号感知降序展示，高版本优先；自定义模型不要求存在于返回列表。
- 主操作常态显示两个固定正圆图标：橙色“重新翻译全文”无视现有译文并逐行覆盖全部字幕，绿色“开始翻译”只处理空译文；旧译文在对应行的新结果成功返回前继续保留。运行中两个入口原位切换为带进度的“停止翻译”。

字幕列表不显示额外的“字幕列表”标题带，也不使用包裹整表的外边框；表头直接落在页面底色上，并用一条主题分隔线与数据区区分，表头文字相对数据区略微上提。数据行按真实位置交替显示为透明行和完整圆角背景块。交替规则不依赖虚拟列表中的 DOM 顺序；表头和行正文保持可读字号、统一行高与垂直居中，当前固定行高为 `46px`，虚拟滚动的估算高度必须随实际最小行高同步调整。

字幕工具内仅在悬停或聚焦时出现的操作背景遵循显示基线：模型入口和译文编辑入口使用胶囊形高亮，顶部文件操作、单句重试等接近正方形的图标热区使用正圆高亮。模型、推理强度等菜单内部选项保持小圆角，并在相邻高亮块之间保留 `2px` 间隔。上下文窗口默认只显示左侧标签和右侧对齐数字；悬停或聚焦时数字输入框从标签右侧开始铺满剩余区域并使用胶囊背景，数字始终右对齐，避免进入编辑时位置跳动。菜单容器和字幕交替行背景保持原有结构圆角。

单句翻译使用固定尺寸的重译图标按钮；常态没有底色，鼠标悬停时才显示按钮底色，请求进行中只显示旋转进度。单句请求绑定当前字幕数据版本和单调请求序号；载入另一份字幕、合并行、手动修改译文、启动批量任务或后一次单句请求后，旧响应不得写回当前草稿。批量任务造成其他行暂时不可操作时，不引入常驻按钮色块，只通过图标状态和可用性表达差异。

推理强度使用紧凑分段控制，提供 `自动 / 低 / 中 / 高`：

- `自动` 为默认值，不向 provider 发送推理强度或固定温度，使用模型或服务端默认行为。
- 批量翻译开始时先创建 main 侧 AI 运行会话，冻结当时启用配置的 provider、Base URL 和 Key；逐行请求复用会话 ID。切换 active 服务不影响当前任务，编辑或删除当前任务使用的配置会被拒绝；停止任务或 renderer 销毁会取消当前在途请求，完成后正常释放会话。
- 批量 Runner 的快照和待消费结果按 `libraryId` 隔离。切到另一资料库时，新库不得显示旧库任务状态、消费旧库译文或停止旧库任务；返回来源资料库后仍可接收尚未写回的结果。全局同一时间只执行一个批量任务，显式在另一资料库启动新任务时会停止前一个任务。
- `低 / 中 / 高` 只在用户显式选择后发送；`OpenAI / DeepSeek / Local` 映射为 `reasoning_effort`，`Claude` 映射为 `output_config.effort`。
- 显式发送推理强度时不再发送 `temperature`，避免部分推理模型拒绝两者同时出现。
- 该控制表达请求偏好，不承诺所有模型都支持；不支持时保留 provider 返回的原始错误，用户可切回“自动”。

字幕任务配置只保存：

- 模型
- 推理强度
- 上下文窗口
- 预设提示词

这些配置保存在本机 `localStorage` 的 `subtitle-translation-preferences:v2` 中，不回写后端。旧版 `v1` 中的 Base URL 与明文 API Key 不迁移并会被删除。

当前支持“预设提示词”：

- 作为每次翻译请求固定附带的 system prompt 补充
- 用于长期术语、语气、专有名词等稳定规则

### 6.3 上下文拼接

当前单句翻译会把：

- 当前句
- 前 `contextWindow` 句
- 后 `contextWindow` 句

一起发给模型，但明确要求模型只返回“当前句”的译文。

默认 `contextWindow = 5`。

### 6.4 QQ 音乐歌词工具

`QQ 音乐歌词` 是 macOS 纯客户端工具。Electron main 只读访问 QQMusicMac 本地数据库：

```text
~/Library/Containers/com.tencent.QQMusicMac/Data/Library/Application Support/QQMusicMac/qqmusic.sqlite
~/Library/Containers/com.tencent.QQMusicMac/Data/Library/Application Support/QQMusicMac/iRRCache/rrdbcache.sqlite
```

当前能力和边界：

- 打开工具后默认按最近访问顺序分页加载本机已有 QRC，可继续加载更多，也可切换到全部曲库；两种范围都支持按歌曲名、歌手过滤，并标识普通 LRC、QRC、翻译和音译缓存是否存在。缓存存在但曲库元数据已清理时仍按 SongID 显示并允许预览。
- 从 `Cache.data` 解开 binary plist 和 hex payload，再用 `smart-lyric@1.0.4` 在 main 内存中解密 QRC；不调用 Python/Node sidecar，不落地原始 QRC，不读取登录态。
- Renderer 使用通用 timed-text parser 生成可拖动、可播放的逐字时间轴预览，并复用音乐播放器的焦点行和连续扫色计算；时间片播放中按内部进度从左到右推进，不整词瞬时变色，句间空隙聚焦下一句。真实 QRC 单词格式为 `文字(start,duration)`，时间标记属于前面的文字；共享 parser 继续兼容历史 `(start,duration)文字` 输入。搜索和预览使用独立的 latest-request 保护，快速操作时旧响应不会覆盖当前结果。
- 第一版只预览主 QRC。QQMusicMac 的翻译和音译缓存目前仍是未解析二进制，不作为可保存结果。
- 工具导航中的 QQ 音乐图标固定使用网易云风格红色，歌曲名搜索框不放内部装饰图标。预览标题栏使用中圆角单图标保存入口；刷新、搜索、保存、播放等图标按钮复用 AI 服务配置的行内操作反馈，常态透明并使用弱文本色，悬停时显示正文色和清晰的中圆角中性底色，不叠加外投影或位移。播放进度使用音乐播放器同类的无圆点渐变轨道，不显示悬浮时间提示，同时保留原生 range 的拖拽和键盘定位。文件名、目标目录和 storage provider 只在点击后打开的紧凑保存弹窗内显示；目标目录可打开资料库目录选择器，确认后按资料库记忆为下次默认值，首次仍按当前目录、当前文件父目录、资料库根目录回退。保存前校验记忆节点仍是当前资料库目录，失效时清除偏好并回退，未经再次确认不上传。弹窗每次打开都回到后端默认 Provider，也允许只针对本次保存切换 Provider，不修改全局默认配置或下一次保存。歌曲目录歌手和 SongID、标题说明、时间轴时间戳和歌词、播放时间以及目录选择器文案等紧凑信息至少使用 `12px`，结果行、时间列、播放栏和目录行随之校准。歌曲列表查询只读取缓存元数据，不加载歌词 BLOB；只有预览时才读取目标 QRC。生成 `.qrc.xml` 后复用本节下方的库内 staging/upload 链路保存到 MinIO。文本 staging 和通用临时导入目录都属于受控上传来源，文件名按 UTF-8 字节限制并保留扩展名。
- Windows / Linux 明确显示不支持；renderer 页面不自行拼系统路径或直接调用原始 IPC。

详细契约见 `docs/qqmusic-lyrics-tool.md`。

## 7. 保存链路

### 7.1 本地另存为

当前链路：

```text
renderer tool workspace
  -> preload save dialog
  -> preload writeTextFile
  -> Electron main 写入目标路径
```

### 7.2 库内另存为

当前链路：

```text
renderer tool workspace
  -> preload createStagedTextFile
  -> Electron main 在 userData staging 下生成真实文本文件
  -> renderer 复用 /v1/directory/upload
  -> 上传成功后清理 staging 文件
```

规则：

- Electron main 只负责“通用文本文件 staging / 写入”。
- 上传业务仍由 renderer 侧现有上传链路负责。
- 工具区生成内容属于系统插入，库内另存调用 `/v1/directory/upload` 时传 `conflictPolicy=auto_rename`；同目录重名由后端返回最终名称，例如 `字幕 (1).srt`。
- QQ 音乐歌词保存复用同一链路，并固定保存解密后的 `.qrc.xml`，不上传 QQMusicMac 的 plist 或加密缓存载荷。

## 8. 状态 owner

当前 owner 规则如下：

- `workspaceDisplayMode`
  - owner：`library detail` 页面
- 目录树当前选中节点
  - owner：目录树组件内部
  - 向页面层只做只读透传
- 字幕翻译草稿
  - owner：`features/tool-workspace`
  - 当前按 `libraryId` 做内存缓存
- 字幕批量翻译运行态
  - owner：`features/tool-workspace/subtitle-translation.runner.ts`
  - 当前只允许一个全局批量任务，但快照和结果按 `libraryId` 投影与消费；跨资料库不得互相 drain 或误停
- 翻译配置
  - owner：`features/tool-workspace`
  - 当前持久化到本地 `localStorage`
- 媒体文件处理请求
  - owner：`library detail` 页面只负责把目录树文件节点一次性送入工具区
  - 工具区只保存当前待处理节点；真实输入仍通过 `nodeId + libraryId` 临时链接解析
- 资源捕获处理资源
  - owner：`features/tool-workspace`
  - 当前由浏览器资源面板一次性送入，只保存在工具区内存中，不写入工具区持久化状态
- 工具导航布局
  - owner：应用级 `SyncedUserPreferencesProvider`
  - namespace：`tool-workspace`
  - 数据库保存 `navWidth / toolOrder`，同一账号跨 macOS / Windows 同步
  - 点击双箭头和手动拖动共用同一个 `navWidth` 状态；点击收起或手动拖到 `57px` 后图标统一转为展开方向，不维护第二份折叠状态；布局 schema v2 会把旧版纯图标宽度 `58px` 迁移到 `57px`
  - 分割线拖拽热路径只更新工作区容器 CSS 变量，由浏览器直接预览导航宽度、按钮位置和内容响应式形态；React 状态与数据库偏好只在松手后提交一次，禁止在每次 `pointermove` 中重渲染整个工具工作区
  - 工具导航、资料库目录树和工具内部局部分隔线各自持有独立拖拽会话；命中区固定为边界中心的 `6px` 窄条，结束、取消、失去 pointer capture 或卸载时只释放自己的 cursor / user-select 状态，不得清空仍由其他 owner 持有的拖拽状态
  - 工具定义、名称、图标和页面组件继续由前端 `TOOL_ITEMS` 定义；数据库只保存稳定 ID 顺序
  - 读取顺序时丢弃未知 ID、去重，并把当前版本新增工具追加到末尾

## 9. 媒体文件处理工具

### 9.1 当前能力

- 从目录树音频 / 视频文件右键“在媒体工具打开”进入。
- 输入源是内部资源库节点，不依赖 embedded browser 资源捕获快照。
- 工具区通过 `getFileLink(nodeId, libraryId)` 获取临时访问链接，再调用独立的 `media-tool:process-file` IPC 交给本地 ffmpeg 处理。
- 当前第一版支持：
  - 提取音频：导出 `m4a`，使用 AAC 192k。
  - 压缩画质：导出 `mp4`，使用 H.264 / AAC、CRF 28、medium preset。
- 输出复用工具区“保存到本地 / 导入到资源库”模式：
  - 本地：写入本地保存目录。
  - 内部：先写入 Electron 临时导入目录，再复用上传中心导入目标目录，成功后刷新目标目录子树。

### 9.2 边界

- 媒体文件处理不负责资源捕获、HLS / MPD 解析、MSE 缓存读取、分片下载或 key 验证。
- 右键入口只面向文件节点；目录批处理和多文件队列后续再扩展。
- 当前只暴露固定参数的两个动作；更细的码率、CRF、preset、音频格式选项后续再加。
- 内部媒体文件处理使用独立 `media-tool:*` IPC，不应调用 `embedded-browser:*` channel。

## 10. 资源捕获处理工具

### 10.1 当前能力

- 从浏览器资源面板接收“已选资源”。
- 从浏览器资源卡接收“已解析 HLS 计划”。
- 展示送入资源的标题、类型、大小、来源和扩展名。
- 合并音视频：复用当前 embedded browser 的本地 ffmpeg 合并链路。
- 转格式：单个媒体资源可输入目标扩展名后通过本地 ffmpeg 尝试转换，扩展名只接受 1-12 位字母或数字，例如 `mp3`、`m4a`、`mp4`、`wav`。如果 ffmpeg 不支持该封装或编码组合，错误直接回传给用户。
- HLS 计划模式：
  - `媒体处理` 内部新增 `直接资源 / HLS 计划` 模式切换，不新开第三个工具。
  - 资源卡中的 HLS manifest 在解析后可点击“送到工具页”。
  - 工具页显示 HLS 计划摘要：playlist 类型、是否直播、分片数、key/map/part 数量、建议线程数。
  - 对媒体 playlist，工具页已补 Cat Catch 风格的第一版下载控制：
    - 线程数
    - 起始分片
    - 结束分片
  - 一旦改动线程数或分片范围，就会强制切到本地 downloader 主链，不再让 ffmpeg 直接拉整条 manifest。
  - 网络 `master playlist` 已支持第一版 variant / 清晰度选择：
    - 默认保持“自动”，继续把原始 manifest 交给 ffmpeg。
    - 也可以明确锁到某个 variant URL，再按该清晰度执行下载。
  - 工具页现在会额外展示 `master playlist` 的音轨 / 字幕轨摘要，并把当前选中 variant 关联到对应 audio group / subtitles group。
  - 当前已支持在工具页里：
    - 选择独立 audio rendition，并走 `ffmpeg` 下载+合并主链
    - 选择 subtitle rendition，并单独下载字幕文件
  - 工具页支持手动输入 16 字节 AES-128 自定义 key（hex / base64）。
  - 工具页也可以直接做一轮 key 验证：
    - 自动候选来源于 manifest 自带 key URL 和当前 tab 已捕获的 key 资源。
    - 如果你已经手动输入了 key，也会一起作为候选参与验证。
    - 当前已开始区分“不需要 key / 还没有候选 / 候选未命中 / 验证过程失败”这几类结果，方便排障。
    - 当前验证会抽前面几段 AES-128 分片一起验证，不再只试第一段。
    - 当前也会把“试了多少候选 / 验了多少片”直接展示出来，方便判断验证结论的可信度。
  - 工具页会显示当前执行状态、最近日志、当前阶段，以及分片完成数；当前日志已按阶段 / 执行链结构化展示，并补了一版任务阶段进度条；失败时还会显示失败分片编号并支持一键复制，便于排障或后续做定向重试。
  - 本地 downloader 下载中会补充已收字节、下载速度和预计剩余时间；`ffmpeg` 阶段会补充处理秒数和速度文本，但仍以阶段状态为主，不伪装成精确百分比。
  - 当前本地 downloader 失败后，工具页已经可以直接“重试失败分片”，不再默认整条任务从头来一遍。
  - 网络 manifest：
    - 继续走现有 `ffmpeg` 直拉主链。
  - blob / 页内内存 manifest：
    - 走 Electron main 的本地 downloader 主链：
      `plan -> local workdir -> rewritten local-playlist.m3u8 -> ffmpeg`。
  - 如果填写了自定义 key，也会强制走本地 downloader 主链，让本地 playlist 引用手动写入的 key 文件。
  - 当前 `master playlist + 手动 key` 仍不作为可用组合；需要先收敛到具体媒体 playlist，再走本地 downloader 主链。
  - HLS 计划模式仍复用统一“保存到本地 / 保存到内部”的保存目标切换，不单独弹第二套保存 UI。
  - 当前下载控制先补了 Cat Catch 最常用的线程数和分片范围；时间范围、IV 等还没补。
- 保存目标切换：
  - 本地：保存位置显示为一行路径，点击路径可切换到系统目录
  - 内部：通过紧凑目录选择器选择目录（面包屑 + 双击进入目录）
  - 内部未选目录时，点击“合并&保存 / 转换&保存”会把路径框标红并提示“必须选择”
- 内部保存链路：
  - 合并/转格式先在本地落盘
  - 再以 `conflictPolicy=auto_rename` 自动上传到所选内部目录（上传失败时提示“本地已保存，内部上传失败”）
  - 上传成功后会触发目录树目标目录局部刷新，立即可见新文件

### 10.2 边界

- 媒体处理工具不重新捕捉资源，不修改资源 URL、后缀或来源。
- 当前转格式一次只处理一个媒体资源；多资源批量转码后续再扩展。
- HLS 第一版只把“计划解析后的重处理”收进工具区；资源面板仍只负责解析、复制计划和发起，不承载长时间下载 UI。
- 当前 HLS 计划模式已补基础执行反馈（阶段 / 结构化最近日志 / 分片完成数 / 阶段进度 / 重新执行），并补了网络 master playlist 的 variant 选择、独立音轨选择与 ffmpeg 合并、字幕轨单独下载，以及媒体 playlist 的线程数 / 分片范围控制；本地 downloader 失败后也已经支持“重试失败分片”，下载中会展示已收字节、速度和 ETA，ffmpeg 阶段会展示处理秒数和速度文本。剩余主要是轨道联动验真和真实样本测试。
