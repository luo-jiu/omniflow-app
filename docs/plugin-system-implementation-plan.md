## 1. 目标、范围与完成定义

本轮工程的终点是：外部作者能够不导入宿主源码，独立构建、手动安装、更新和停用一个只读查看器；宿主保持基础浏览、权限、主题、标签页和资源回收的控制权。

近期交付按顺序为：

1. 颜色主题和图标包可独立选择，统一解析且有内置回退。
2. 命令、菜单和查看器有稳定贡献入口，原有行为通过内置适配保持兼容。
3. 第一方只读 CSV 查看器通过公开 SDK 独立构建，完成开发加载到关闭回收的完整链路。
4. 手动安装、兼容检查、授权、停用、升级失败恢复和禁用第三方启动可用。
5. 第二个不同功能的样板验证 SDK 复用，并提供外部开发者使用的模板与文档。

A0～D2 的初始范围不开放文件写入、批量改名执行、任意网络代理、本机目录访问、Shell、Node.js、Python、原生二进制、服务器插件、存储驱动、插件依赖图和商城。后续 W0～W2 仅增加由插件生成提案、宿主批准并执行条件改名的窄能力；正文写入、移动、删除等仍未通过插件 SDK 开放。插件自身的有界设置与阅读状态存储不等于允许修改用户文件或节点 `viewMeta`。

静态注册表只是第 1 阶段准备。具备独立身份、包清单、公开接口、加载与实例生命周期、兼容检查、停用和失败回退后，才称某个功能已经插件化。现有全部查看器和工具不要求一次性迁移。

## 3. 状态 owner 与依赖边界

| 状态或能力 | 权威 owner | 插件能获得的内容 |
| --- | --- | --- |
| 账号、登录、原用户权限 | 现有认证链路及后端 | 经裁剪的上下文，不含令牌 |
| 资料库和节点事实、事务 | 现有业务服务及后端 | 授权范围内的资源引用和读取结果 |
| 工作区模式、树选择/展开、tab | 现有页面、useRepositoryTree、FileViewerContext | 上下文快照、变更通知和受控打开请求 |
| 播放与上传 | 现有媒体服务和上传中心 | 首期不开放；不能另建全局 owner |
| 主题解析 | 现有 ThemeContext 演进出的单一解析 owner | 版本化只读快照 |
| 包安装记录、实例身份、授权、句柄 | 新增 Electron 插件宿主 | 宿主绑定的会话及有限能力，不能自报身份 |
| 查看器阅读状态 | 既有 Session owner 经插件适配扩展 | 自身命名空间内的有界可序列化 payload |
| 插件设置 | 宿主管理的隔离存储 | 自己账号/适用资料库范围内的设置 |

建议职责落点（目录名在对应批次冻结，当前均不表示已创建）：

- `src/features/extensions/`：贡献投影、选择器、管理界面和现有工作区适配。
- `src/features/appearance/`：主题解析、token/图标语义和 UI 适配；由既有 ThemeContext 接入。
- `src/service/extensions/`：宿主 renderer 的有类型桥接，不承载页面状态。
- `electron/service/extensions/`：包校验、运行实例、权限执行、句柄和强制回收。
- 独立 SDK 包与样板包：不依赖 `@/`、宿主 React Context、Electron 内部文件和应用 node_modules 的隐式依赖；包名、目录和构建输出在 C1 冻结。

包生命周期位于 Electron，tab 生命周期留在 FileViewerContext。两者通过实例与 tab 绑定适配协同，不互相复制状态。即使初版只运行第一方样板，也不得为其 ID 添加私有权限后门。

### 4.1 A0：运行基线与最小决策

1. 重新核对受影响文件的当前差异和上述代码事实，记录验证对应的提交及未提交差异范围。
2. 执行一次现有 lint/test/build，区分已有失败与本工程引入的问题；已有失败必须可定位，不静默跳过。
3. 在隔离 fixture 和允许的资料库记录：冷启动、无插件空闲资源、目录展开/滚动、文件打开、切 tab、切主题、打开 overlay、关闭与释放资源。记录机器、平台、应用版本、样本规模、采样方式和原始结果；性能预算在 C1 用同一方法测量后冻结，D1 前必须有具体数值。
4. 盘点 token 消费面：主壳、树、tab、菜单、表单、Semi、编辑器、overlay 和原生不透明窗口背景；记录暂不纳入的特殊品牌视觉及原因，不宣称其已完整主题化。
5. 建立旧工具 ID/顺序、旧 tab、Viewer Warm/Cold、Text dirty draft 的兼容 fixture，正文使用合成内容。
6. 明确主题模式与颜色主题 ID、图标包 ID、用户覆盖是不同字段；决定登录前/后的偏好来源、账号切换和预览提交规则。

退出：上述清单和实测记录齐全，A1/B1 的输入与失败回退可直接实施。

### 4.2 A1：主题与图标基础

- 将系统默认 → 主题明暗变体 → 用户覆盖解析为一个快照，包含 schemaVersion、递增 revision、选择信息、resolvedMode 和解析后的 token。名称为设计候选，正式 schema 随代码冻结。
- 沿用 `--app-*`，增加缺失的交互、焦点、禁用、状态、归档和编辑器语义；Semi、styled-components、CodeMirror 只消费适配结果。
- 预览不写持久偏好；取消恢复已提交选择；账号切换终止旧预览与迟到保存；主题缺失/非法回退内置，保留可诊断原因。旧 `app-theme` 和历史用户模式继续有兼容读写语义。
- 主窗口解析，main 仅缓存/转发最新快照并应用必要的原生颜色投影；overlay 首次握手、重建和切换均收到完整快照，拒绝旧 revision。不得在各窗口重新解析同一主题；首帧默认主题作为加载兜底，不作为第二 owner。
- 图标解析产出语义键与状态，再选择资产，最后叠加宿主必要提示。颜色选择与图标选择互不修改；目录开合取现有 expanded 投影，不写回节点事实。
- 首批使用内置声明式主题与图标包验证；外部包安装在 D1 开放。资产和颜色校验与后续包加载复用，拒绝脚本、远程引用、越界路径和危险 SVG。
- 暂不公开单节点外观持久化和复杂用户关联编辑器，但解析接口保留方针规定的优先级；未提供的层级直接跳过，不伪造可用功能。

退出：两种颜色方案 × 两套图标组合、明/暗/系统、缺 token/缺图标、预览取消、缺失回退、主窗口/overlay/编辑器都通过；目录类型、双击、展开和现有标题栏透明策略不变。

### 4.3 B1：命令、菜单与工具贡献入口

- 建立命名空间命令 ID、标题、受控参数 schema、适用上下文和执行入口。菜单只声明位置、顺序、命令 ID 和有限的可见/可用条件，不执行任意表达式。
- 第一批接入工具导航和一组既有目录菜单动作，中文标签留作展示；兼容适配将旧动作映射到原有业务执行路径，逐步缩小旧字符串使用面。
- 内置高权限动作继续由宿主执行。命令已注册不代表插件可调用；先定义插件可调用白名单与逐次权限校验，其余动作不向 SDK 暴露。
- 工具贡献收敛元信息和加载入口，保留字幕草稿、媒体任务等原 owner。系统设置、认证和上传管理等核心界面不因有注册表就变成可停用业务插件。
- 工具排序持久化与当前可用贡献分开：未知但格式合法的 ID 保留排序意图，渲染时过滤；重新启用可恢复顺序。损坏 ID 拒绝。旧 ID 映射稳定，已有工具默认顺序和草稿不丢失。
- 重复 ID 拒绝整个有冲突的贡献加载事务，不按安装顺序覆盖；预检通过再原子发布，失败撤销本轮注册。

退出：增加一个内置示例命令/工具入口无需修改多处主壳分支；原菜单行为与工具排序恢复通过；当前仍明确标为内置贡献机制。

### 4.4 B2：查看器选择与 Session 兼容

- `fileType` 保持事实投影；新增稳定查看器贡献身份，概念为 `pluginId + viewerId`。匹配输入限于宿主提供的扩展名、MIME、识别结果和资源类别，不借匹配读取正文。
- 选择顺序：用户本次指定 → 有效的已保存关联 → 既有内置默认/明确候选规则。新增插件只进入候选，不静默接管打开方式；并列候选规则确定且可解释。
- 同一文件仍默认复用 tab；在 tab 内切换查看器时更新实例 generation，释放旧实例并忽略迟到回包。原 Text dirty draft 的 hot-exit/冲突处理语义保持，插件切换不得清除。
- 将查看器身份纳入恢复命名空间与策略解析，保持旧内置 key 的兼容读取。不得全局放宽 `isViewerKind`、丢掉账号/库校验或允许插件自定无上限保活策略。
- 为旧 snapshot、不同插件同格式、插件 schema 升级和缺失定义解码/失效规则。阅读位置无法迁移时允许丢弃有界 UI snapshot 并提示；正文草稿不按同样策略丢弃。
- 无插件、插件停用或不兼容时保留文件引用与必要恢复数据，显示内置查看器或原始文件导出入口；临时回退不覆盖用户保存的插件关联。
- 本地预览、归档类型、媒体 owner 和原有返回目标先保持现有路径。

退出：旧文件打开/关闭和恢复行为通过；两个同格式贡献不串状态；缺失插件仍可浏览和导出；不存在第二套 tab 或媒体状态源。

### 4.5 C1：最小 SDK 与隔离方案实验

开发加载也只能运行在拟定的受限环境中，不能临时把插件脚本 import 到主 renderer，再承诺以后补隔离。

| 需冻结的契约 | 最小内容 |
| --- | --- |
| Manifest | 插件 ID、版本、SDK 范围、平台、入口、激活条件、贡献、必要能力和权限请求；包格式版本单独管理 |
| 消息协议 | 协议版本、请求 ID、方法、可序列化参数、明确错误与取消；身份由宿主绑定来源，不信任 payload |
| 上下文 | 当前获准资源引用、主题、活动状态；上下文可见不自动授权正文 |
| 资源读取 | 仅打开的已授权节点；主机持有短期句柄，支持有界分块、取消和版本变化检测；原始 URL/凭据不透出 |
| 阅读状态/设置 | 插件与账号及适用库隔离；schema/revision、配额和非法值错误；不暴露宿主全部偏好 namespace |
| 生命周期 | 激活、就绪、活动/挂起、捕获/恢复、关闭、强制销毁；请求超时和迟到回包规则 |
| 错误 | 至少区分拒绝授权、资源失效、版本变化、能力缺失、不兼容、超限、取消和运行终止；名称随 schema 冻结 |

资源 broker 必须验证节点确属目标库、当前用户可访问且插件获准；现有 API 不足以证明时补最小宿主/后端能力或保持不可用，不能仅凭 renderer 给出的 nodeId 放行。签名链接及其重定向由宿主验证目标范围，不能退化成任意 URL 请求代理。

实验比较 iframe 与独立 WebContents/进程组合，不预设每插件一个进程。必须实测：

1. 无主 DOM、通用 IPC、Node、文件、认证 session 和令牌旁路。
2. 独立 origin/session、导航、新窗口、下载、权限请求、包资源路径和网络默认拒绝；覆盖 fetch、WebSocket、图片、媒体、表单等出口，不能只限制 SDK 或 connect-src。
3. 样式隔离、嵌套浮层、原生 view 遮挡、焦点和键盘行为。
4. 死循环、无响应和崩溃时，宿主可以独立停止实例且主窗口保持可操作；单独 Worker 或 Shadow DOM 不能被当成完整方案证明。
5. 并发请求、单次数据量、总读取量、句柄数量、快照、日志、包大小、解包量、启动/关闭超时均有具体限制和超限行为。数值通过 CSV 与恶意 fixture 实测冻结；无界实现不得进入 D1。

退出：写入隔离决策记录（方案、证据、否决原因、已测平台、限制）；独立 SDK/样板构建完成，不借用宿主 alias；未通过强制停止或网络边界的方案不能进入第三方阶段。

### 4.6 C2：CSV 第一方完整样板

- 插件独立身份、Manifest 和构建产物，首次使用通过宿主命令/“打开方式”选中，不修改文件识别结果。
- 首期支持 UTF-8 CSV（含 BOM、CRLF、引号、转义引号和字段内换行），明确其他编码/格式的未支持提示。显示值按文本渲染，不求值、不执行 HTML 或表格公式。
- 读取经受控句柄，插件完成解析和表格呈现。大文件分块处理、行列/单元格长度和内存有界；超限或不完整内容明确提示，不显示成完整空表。
- 支持主题切换、活动/挂起、滚动位置等轻量恢复、取消加载、关闭和重新打开；未开放媒体与文件写入。
- 覆盖授权拒绝、读到一半撤权、节点内容变化、切库/账号、重复/迟到回包、读取失败、解析失败、崩溃和停止。
- 日志按插件/实例/请求定位，正文和凭据不默认入日志，日志量有界。

退出：独立构建 → 开发加载 → 授权 → 打开 → 读取/显示 → 主题/恢复 → 关闭/故障回退贯通；“只读”只限制副作用，不降低权限与隔离要求。

### 4.7 D1：安装、授权与恢复

- 在现有宿主「设置」内交付「插件管理」页面：本地包安装、插件列表/详情、版本与兼容状态、启用/停用、权限查看与撤销、本地包更新、卸载及失败日志入口。列表为空、加载中、失败、被阻止、运行中与操作进行中必须有明确状态；状态来自宿主，不由页面另建安装事实源。
- 「外观设置」独立于插件管理，承接 A1 的颜色主题/图标包选择、预览、取消与恢复默认；同包外观可用不代表代码获准执行。C1 先交付最小开发加载与诊断入口，D1 形成用户管理闭环；商城不在首期范围。
- 支持本地包手动安装，安装先进入 staging，验证清单、SDK/平台、重复身份、完整性、包内路径、符号链接、大小及解包边界后发布；不执行安装脚本。
- 安装记录和实例状态分离。安装/启用外观贡献不自动激活同包代码或授予读取权限；授权展示真实用途、范围和新增权限。
- 授权取原用户权限 ∩ 插件授权 ∩ 当前资源范围；每次调用复验。切账号销毁旧实例与能力；切库关闭旧库句柄和实例绑定，保留由现有 owner 管理的合法工作区恢复信息。
- 停用先停止准入和撤销句柄，再取消在途读取、移除贡献、销毁实例；正常关闭允许有界状态捕获，异常/撤权不等待插件。已交付给插件的字节无法追回，不承诺撤权抹除历史读取。
- 升级在隔离 staging 预检，旧实例关闭后才替换；失败保留可运行旧版本。涉及持久数据升级必须证明旧版兼容或备份恢复；首期避免不可逆迁移。
- 卸载默认保留用户文件和插件持久数据；单独提供明确的数据清理操作。失效 UI snapshot 可按既有配额清理，不把草稿当缓存删除。
- 提供无需成功激活第三方即可进入的恢复入口：禁用第三方代码启动、查看失败原因、停用坏插件、恢复内置主题/图标；损坏外观不能遮蔽恢复界面。

退出：管理页面中的安装、权限、启停、更新、卸载和失败恢复可操作且与宿主状态一致；坏插件无法阻止进入管理/恢复界面；安装失败不留下半注册贡献；更新失败可恢复；越界请求全部失败；死循环可停止；未启用插件不执行代码；重启后状态一致。

### 4.8 D2：复用与外部开发验收

第二功能暂定只读 JSON 树查看器，使用相同资源读取、主题和生命周期接口，与 CSV 的表格解析/呈现不同。另准备第二个 CSV 测试贡献专门验证匹配冲突，不把它当第二种功能的复用证明。

- 第二样板不得增加插件 ID 特判、插件专属 IPC、专属后端入口或导入宿主模块。
- 从宿主仓库之外的干净目录，仅使用发布候选 SDK、模板和文档构建、安装、更新样板；记录依赖安装、构建、兼容宿主版本和结果。
- 文档提供 Manifest/schema、类型、错误码、授权、开发加载/刷新、日志定位、包格式、更新/停用及限制，示例命令必须真实可运行后再写为正式操作步骤。
- 第一期支持平台以实际验收结果声明；本机 macOS 验证不能代替 Windows 的 DPI、标题栏、原生视图和包安装测试。未测平台明确未验证，不放入已支持清单。

退出：方针的“他人独立开发”“官方插件使用公开 SDK”“第二插件无需主壳专用修改”有可复现证据。

## 5. 关键状态流与兼容要求

安装状态候选：未安装 → 校验中 → 已安装；校验失败保持原状态。启用/停用及被阻止原因单独记录，不用“已安装”推断可以运行。

实例状态候选：未激活 → 启动中 → 就绪 → 活动/挂起 → 停止中 → 已销毁；任何运行态可因故障进入隔离/销毁。就绪前不能处理正文访问，销毁后所有旧请求和回包失效。

宿主绑定至少包括插件 ID、包版本、实例 generation、真实消息来源、账号、库、tab 和授权 revision。插件选择资源不会改变这些绑定。恢复后的新实例必须重新取得能力，不能从 snapshot 恢复有效句柄。

| 变化 | 兼容与回退要求 |
| --- | --- |
| 主题字段扩展 | 旧明暗/系统偏好可读；缺包回退；旧账号初始化和迟到请求不覆盖当前选择 |
| 工具 ID 扩展 | 旧 ID 保持或显式映射；保留未知合法贡献排序；现有字幕草稿不被新归一化丢弃 |
| 查看器身份扩展 | 旧内置 key 可读，插件间隔离；旧应用回退所需数据保留；不得无声清空整个数据库 |
| 插件停用/缺失 | tab 文件引用、用户文件、必要恢复数据保留；可用内置查看器或导出 |
| 内容 revision 变化 | 旧流/快照按规则拒绝或失效；不把两个版本字节拼成一个文件 |
| 切库/账号/退出 | 撤销能力、终止实例、忽略旧回包；沿用既有工作区与持久草稿边界 |
| 包版本回退 | 代码与数据兼容一起验证，不只替换 zip；失败不会自动扩大权限 |
