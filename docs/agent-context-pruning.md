# Agent 旧正文清理

更新时间：2026-09-09

## 范围

参考本地 OpenCode `packages/opencode/src/session/compaction.ts` 的 prune/protect 分层，增加确定性的旧读取正文清理。后续再参考 `packages/core/src/session/compaction.ts` 的 prior-summary/conversation 有序合并，调整当前 Run 摘要候选与提示词；不替换跨 Run 历史摘要或权限状态机。

本轮只在 Active Context 超过当前请求预算时尝试清理。没有压力时不改上下文；清理后仍不够，再走原来的语义摘要。这与 OpenCode 主动 prune 的调用时机不同。

## 当前 Run 有序摘要

- 合并相邻的可摘要 Tool 轮次时，允许中间存在普通用户/助手文字；这些文字参与时间线解释，但提交时原对象、内容和相对顺序仍保留，不因摘要丢掉用户要求。新摘要置于已处理片段末尾，后面的近期消息保持原样。
- 可合并此前带内部来源标记的摘要，并在 payload 中标为 `previous_summary`；用户伪造相同文本前缀不能获得该标记，也不会作为旧摘要被删除。
- payload 的 `sequence` 和 `coveredRange` 明确当前历史片段顺序；`currentUserTask` 只用于相关性，不是执行回执，也不声明它与片段的先后关系。提示词要求较新的有据事实更新旧摘要，不把“请重新读取”倒推成“已重新读取”，不把片段未含事实误写成全局未执行。
- 摘要提示词显式说明每字段24条、每条1000字符、总JSON8000字符的限制。若模型在总长度范围内返回过多短条目，逐条完成类型/长度/敏感信息/授权措辞校验后按原顺序用换行无损合并，直到满足条目数限制；不切掉尾部事实、不提高长度预算，无法满足边界仍失败回滚。该逻辑用于消除条目分组造成的无谓失败，不是另一轮语义摘要。
- 已观察的路径/revision/数值与“当前状态未知”分开表述；无关资料要求类别性概括，但这仍是模型提示，不是确定性语义过滤，实测仍可能保留多余标识符。
- 未消费结果、禁止摘要的记录及受保护近期轮次仍阻断候选合并。整轮 Tool call/result 配对不拆开；现有原子提交、失败回滚和 ledger 失效规则不变。
- 扩大候选前检查800,000字符保护门槛，并由 Orchestrator 使用真实摘要 payload、system prompt 和输出预留检查模型窗口；不够则分批，不截断证据。单个不可再拆候选仍走原有摘要输入预检，不能通过取消预算校验强行请求。

这不是完整移植 OpenCode：不改摘要 JSON V1、不删除普通对话文字、不采用其 Tool 正文2,000字符序列化截断，也不调整40k/20k正文清理阈值或正式模型窗口。压缩 UI 状态投影暂未改动。

## 规则

- 保护最近两个完整 assistant Tool 轮次，以及最近约 40,000 tokens 的工具输出；跨越 token 边界的整条结果也保留。
- 只有预计释放至少 20,000 tokens 时才应用清理，阈值使用现有本地估算器。
- 只清理已交付、已被模型消费、允许压缩的成功 `file.read` 正文，且要求完整的 scope、path、revision 和 `hasMore=false`。
- 未消费结果、尚有后续的读取、失败结果、写入回执、Skill 和未知格式不清理；混合或未完成的 Tool call/result 轮次仍受原有配对校验约束。
- 不删除调用或结果消息，不改用户约束、助手文本、调用参数与 ID，也不改 SQLite 原始 ToolRun 记录。清理仅替换当前模型消息中的 content 大字段。
- 保留路径、版本、范围等元数据，附带 contentPruned、sourceToolCallId 和明确的有损清理说明。缺少正文不等于空文件，也不证明原始证据仍可从当前文件恢复；需要时按原路径和 revision 重新读取，版本变化则不能猜测旧内容。

## 原子性与计量

在暂存消息和记录数组上创建替换对象，不原地修改原始消息。后续摘要失败时不提交暂存清理；成功提交时通知既有 onCompacted，使上下文计量重新建立基准。prunedToolCallIds 与语义摘要的 compactedToolCallIds 分开返回。

同一正文有清理标记后不重复处理。本轮不新增 UI 开关、远端接口、证据检索工具或跨 Run 清理；`pruneReadBodies=false` 仅用于内部对照测试。

## 验证

确定性对照使用相同超预算 fixture：关闭清理时调用一次摘要模型 stub；开启后无需摘要调用即能放入预算。验证近期正文、最新用户要求、禁止覆盖约束、恢复定位信息、原始结果对象、特殊结果保护及失败回滚。

这证明执行规则与预算行为，不证明 LLM 在多次有损压缩后的语义完成率。下方隔离预算实测另行覆盖有限样本的连续摘要和证据回查，真实长任务仍待评估，不能等同于完整 OpenCode 压缩器迁移。
