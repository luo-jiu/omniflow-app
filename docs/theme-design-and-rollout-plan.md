# 主题视觉设计与推广计划

更新时间：2026-09-23

状态：T1长期样板已可用，T2共享基础与T3代表页面接入持续推进；整套视觉定稿和全页面迁移尚未完成。适用范围为 macOS 宿主外观及第一方插件的主题适配；Windows/Linux 暂缓。

本文负责视觉目标、实施顺序和完成标准。[外观系统](appearance-system.md)负责当前实现事实，[显示基线](ui-display-readability-baseline.md)负责字号、密度与桌面可读性，[插件与主题方针](plugin-system-and-theming-policy.md)负责扩展边界。共同服务[项目长期方针](../../PROJECT_PRINCIPLES.md)中的连续操作体验。

## 1. 当前问题与下一阶段目标

当前已具备单一主题 owner、三套内置配色、明暗变体、67 个颜色角色、受限阴影/圆角、预览/保存/取消、跨窗口快照和宿主统一颜色动画。紫罗兰完整定义了颜色数据，部分主壳、控件和插件样板已接入；这不能代表全产品已有一致的视觉层次。

用户难以判断重点的原因是：目前工程主要回答“颜色如何传递”，尚未把角色落实为一套可比较的表面层次、操作优先级和控件状态样板。页面复用程度、组件库适配和独立样式也不一致，继续逐页调整会重复设计同一类按钮、边框和选中状态。

下一阶段的交付目标：用户在文件、设置、Agent、工具之间切换时，能够沿用相同的视觉判断识别当前位置、当前选择、可执行操作和异常状态；紫罗兰在这些区域呈现同一套风格。

保留森林/海蓝和已有用户选择，紫罗兰继续作为独立选项。共享组件改造要同时回看原配色；不能为统一新主题而直接覆盖默认主题。内部图标库重绘仍由用户另行安排。

本次抽样核对的具体依据：

| 当前事实 | 代码依据 | 规划归属 |
| --- | --- | --- |
| 自定义强调色只改主色、链接、焦点，已有悬停/按下/前景角色未一起变化 | [AppearanceSettings](../src/features/appearance/AppearanceSettings.tsx) | T2 确定成套关系 |
| 初始Semi适配缺`bg-3/4`和独立禁用变量；本批已接现有表面/文字/填充角色 | [适配器](../src/features/appearance/theme-adapters.ts)、[标签管理](../src/views/tag-management/index.tsx) | T2基础接线，消费范围见通用主题基础 |
| 侧栏图标按钮、菜单、设置管理按钮各自定义不同 hover 组合 | [侧栏按钮](../src/views/library/detail/icon-button-styles.ts)、[菜单](../src/components/ui/menu-content/index.tsx)、[设置](../src/views/settings/index.tsx) | T1/T2 区分控件类型并固化状态规则；不能只凭不同就判断为错误 |
| 视频控制面板、进度条仍有独立固定配色 | [视频样式](../src/features/file-viewer/components/video-viewer/style.ts) | T3 媒体外围适配，保留实际内容原色 |

这些证据属于抽样源码核对，尚未构成全页面视觉审计。

## 2. 先确定视觉重点

首版建议方向为“安静的阅读工作区”：内容保持主体地位，紫色集中承担定位、选择和关键操作，表面通过明度与少量色相区分。以下是待样板验证的设计规则，不表示当前页面已经满足。

| 视觉角色 | 用户应读出的信息 | 建议规则与既有入口 |
| --- | --- | --- |
| 页面底、侧栏、内容面板、浮层 | 区域归属与前后层次 | 先明确 `surface.*` 的使用关系；卡片不必一律加边框和阴影，同一层使用一致的分隔方式 |
| 正文、辅助信息、弱信息、禁用 | 信息重要性与可操作性 | 统一消费 `text.*`；必要说明不能靠极低对比度退后，禁用与次级文案需可区分 |
| 当前工作区、选中项目、鼠标经过、键盘焦点 | 我在哪里、选中了什么、下一步操作什么 | 分别使用 `navigation.active`、`control.selected.*`、`interaction.*`、`focus.border`；选中后仍能看见焦点 |
| 主操作、普通操作、危险操作 | 操作优先级及风险 | 主操作使用 `accent.*`，普通操作保持低视觉重量，危险操作遵循 `status.danger.*`；不会把所有按钮都涂成紫色 |
| 成功、警告、错误、信息 | 业务状态 | 状态语义独立于品牌色，配合文字或图标表达；切换主题后含义保持稳定 |
| 毛玻璃、边框、阴影、圆角 | 材质与控件家族 | 保留原生侧栏透色；明暗分别校准。字号与密度遵循显示基线，不随配色任意漂移 |
| 文档、图片、视频、网页与品牌标识 | 内容本身 | 保留内容原色；宿主工具栏、舞台和状态提示按各自角色适配，特殊舞台与品牌色登记例外 |

先使用现有语义角色。发现缺口时记录具体消费者和视觉含义：相同语义用法不一致，应修正接线；独立且可复用的新语义才评估新增 token。不能按每个页面名称无限扩充主题字段。

## 3. 用页面类型组织覆盖

以页面类型和共享入口管理推广，不要求用户逐页找颜色。下面是代表场景与核查入口，状态均为“待按本计划复核”，已有单项验证不等于整类验收。

| 页面类型 | 代表场景 | 要统一的主要视觉关系 | 代码入口 |
| --- | --- | --- | --- |
| 工作区外壳与导航 | Win 资料库：目录树、工作区切换、文件/设置标签 | 侧栏材质、主背景、激活/选择/焦点、分隔与滚动条 | `views/library/detail/layout-styles.tsx`、`FileTabsBar.tsx`、`features/file-explorer/components/directory-tree/` |
| 表单与管理 | 外观设置、插件管理 | 分组层次、标签/说明、输入框、按钮优先级、禁用/错误态 | `features/system-workspace/views/settings/`、`theme-adapters.ts` |
| 列表、表格与任务结果 | 一个工具列表、插件命令记录 | 行、选中/悬停、工具栏、空态、进度/失败状态 | `features/tool-workspace/`、`features/plugin-commands/` |
| 阅读与编辑 | 文本编辑器、图片/视频/PDF 外围 | 内容与工具栏的边界、编辑选区/光标、媒体舞台例外 | `features/appearance/editor-theme.ts`、`features/file-viewer/` |
| 会话与交互卡片 | Agent 消息、输入区、工具确认卡 | 正文/代码/用户消息、操作与状态的视觉优先级 | `features/agent/AgentWorkspace.tsx`、`features/agent/components/` |
| 浮层与隔离页面 | 右键菜单、紧凑确认、属性 overlay、JSON 转换插件 | 与宿主一致的表面/文字/焦点；明确独立渲染边界 | `components/ui/menu-content/`、`components/ui/compact-confirm.ts`、`overlay/`、`samples/json-transform/` |

当前覆盖表见[主题接入覆盖地图](theme-adoption-map.md)，记录共享入口、仍独立的交互、固定色热点和内容例外；已验证场景另链接矩阵。进度以完成的页面类型和状态场景报告，不以CSS替换次数、token数或截图数量计算完成度。

## 4. 推进批次与交付物

### T1：建立一份能做决定的样板

交付可长期查看的「设置 → 外观 → 主题预览」，作为共享组件的样式对照页，开发模式另保留快捷入口。复用真实共享组件与主题 owner，只作临时预览，不另建主题状态。样板包含：

- 同一内容的森林/紫罗兰、亮/暗对照，明确表面、文字与操作重点。
- 树/标签/列表选择、表单、菜单和确认浮层的代表片段。
- 默认、悬停、按下、选中、键盘焦点、禁用、错误等真实可交互状态。
- 实际 Win 资料库的目录树＋标签＋阅读区域，用于确认样板在真实内容中成立。

借此确定紫色使用强度、表面明度差、辅助文字对比和毛玻璃着色。Agent 提供有取舍的推荐稿，用户主要评估整体观感，不需要逐个指定颜色值。复用现有显示校准思路；先核对已有入口能否扩展，不同时维护多套临时演示页。

退出标准：视觉角色与实际样板对应；明暗两版都能区分内容、选择和操作；用户对代表场景的观感有明确反馈。整体风格尚未成立时，先在样板内调整。

### T2：把规则落实到共享入口

按样板统一表面/文字角色、Semi 适配、共享按钮/输入/菜单/确认框及选中/焦点规则，同时完成工作区外壳的接线。每个入口说明影响哪些页面类型，检查森林/海蓝兼容。

同步决定“自定义强调色”的产品语义。当前它只覆盖主色、链接、焦点三项，悬停/按下/主色前景等可能仍来自原配色。需要在样板中决定它继续作为受限覆盖，还是形成经过对比度校验的完整强调色组；该决定不能以补一两个局部颜色代替，也不能默默改写已保存选择。

退出标准：同类控件在代表场景中使用同一套状态规则；新增页面可以直接复用；共享入口覆盖表可核对。现有 token 已有合适语义时不扩展 schema。

### T3：按页面类型推广并处理例外

先推广表单/管理和列表/表格，再处理 Agent、编辑器/媒体及浮层/隔离页面。每类先选一个实际场景，通过后迁移该类剩余独立样式。能在共享入口修复的问题集中修复，不复制整套 CSS 到业务页。

特殊内容保留明确例外：视频/PDF 舞台、封面取色、品牌图标、代码语法等逐项确定归属。Agent 内部语法色目前只统一了动画，尚不接受配色包覆盖；独立插件必须主动消费主题快照，旧安装包需要重建更新。不能因为“没变成紫色”就强制修改所有固定色。

退出标准：第 3 节每类都有代表性亮暗与交互验证；遗漏组件和例外有归属；宿主日常流程不再出现无解释的旧配色或另一套同类控件规则。

### T4：收口为可维护的主题制作规范

在角色和组件消费稳定后，整理主题作者指南：每项颜色的用途、推荐搭配、明暗关系、前景对比、继承回退和限制；第一方插件以同一规则提供适配示例。

声明式第三方主题/图标包的安装分发仍是独立能力，不能把颜色快照或主题指南视为已开放安装。字体、密度、间距的可定制范围继续依据显示基线另行评估。

退出标准：维护者能从样板和指南判断新增控件应该用什么角色；新增配色可以复用既有页面消费，无需重写每个业务页面。

## 5. 验证与范围控制

每批选择受影响的代表场景与最关键边界，遵循现有 lint、测试、构建和手验要求。不在每次颜色微调后重新逐页遍历全应用；共享组件变化须覆盖其代表消费者，跨类型推广后再做一次汇总回看。

- 固定使用非第一个资料库；当前优先 Win / macOS 本机 MinIO。样板尽量使用静态资料与无副作用控件。
- 检查明暗模式下的正文、次级文字、实心按钮前景和状态文字对比度；首版以普通可读文本 4.5:1、关键控件边界/焦点 3:1 为校验目标，透明表面按实际合成背景核对。既有例外记录后逐批处理，不宣称已全局达标。
- 检查所选场景的窄工作区、长文字、键盘焦点、选中与悬停叠加、禁用和错误态。
- 保留预览取消与默认外观回退；颜色动画复用同文档统一时间线，不为每类控件另建切换动画。
- 检查宿主与 overlay/插件的最终颜色一致；跨窗口、原生材质不承诺逐帧同步。
- 不为主题改造重排全部页面、不接管业务状态、不重绘图标库；发现确有结构问题时单列成有场景依据的后续事项。

## 6. 当前交付与下一步

用户确认优先覆盖可复用的基础：背景、文字、归档高亮、选中及交互状态。T1样板和T2的一批通用规则共同推进，避免样板采用另一套仅用于演示的样式。

基础组件/CSS样式及ResourceLabel已经服务真实目录树、外观设置与侧栏按钮；本轮继续收拢普通/危险/禁用菜单、设置分类与管理按钮、插件管理/命令/M2宿主审批区、工具导航/保存路径/字幕操作、四类归档卡片普通表面和视频字幕工具台。输入外观与尺寸分离，旧页面可复用而不改密度；新增描边按钮与独立elevated表面角色消费，不扩展67色schema。样板补充相同的表面、描边操作和真实菜单组件。

资源监测图表改用同一个只读主题快照的目标色，消除从页面颜色动画中间帧取色后不再更新的风险；Canvas不承诺跟随DOM逐帧插值。`npm run theme:audit`用于发现未定义静态变量及生成源码线索，覆盖地图负责解释真实语义，二者不能替代视觉验收。

隔离插件侧同步补齐CSV Viewer、CSV Tool附带Viewer、JSON树、漫画样板和只读生成模板的相关颜色语义、亮暗fallback及递增快照处理；开发包附带主题接入说明。它们保持独立CSS和构建，不依赖宿主组件；源码与独立构建通过不等于用户已安装版本已更新或已完成视觉验收。

本轮按用户锁屏期间持续开发的要求不操作界面。代码接入和自动验证结论写入[验证矩阵](frontend-validation-matrix.md#310-主题--布局--浮层)，解锁后集中检查样板与代表消费者；不把此前样板的GUI证据套给新增迁移。

接着按覆盖地图收拢尚独立的管理/Agent控件与浏览器资源面板，依据样板反馈校准视觉层次。T2的完整强调色组仍需确定产品语义，T4完整主题制作指南应基于稳定消费面整理；已有插件主题接入说明只覆盖消费端。当前配色继续保留，后续修改需说明改善哪条规则、影响哪些页面类型；不声称T1～T4全部结束。
