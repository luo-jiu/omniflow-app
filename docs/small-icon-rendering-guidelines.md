# 小尺寸图标清晰度规范

更新时间：2026-08-19
适用范围：导航栏、工具栏、列表操作、目录树和其他以 `14px～20px` 展示的应用图标。

## 1. 问题背景

工具工作区左侧导航曾混用三类图标：

- Semi UI 的 `24×24` 通用图标。
- 项目素材库中的 `16×16` 或 `32×32` SVG。
- 使用普通字体渲染的 `AI` 字标。

它们即使都设置为 `16px`，实际观感仍会出现大小不一、发虚和边框像缺失的问题。原因是 CSS 宽高只规定图标画布，不代表可见图形的大小与清晰度一致。

典型问题：

- `24×24` 图标缩到 `16×16` 的比例是 `2/3`，原始整数坐标容易落到三分之一像素。
- 细描边、虚线、复杂曲线在小尺寸下会被抗锯齿分摊到多个像素，形成灰边。
- SVG 的 `viewBox` 内部留白不同，相同外部尺寸下可见面积不同。
- 字体的 `font-size` 是字面框高度，不是大写字母的实际可见高度；系统字体不同还会导致 macOS 与 Windows 观感漂移。
- 图标原始造型可能故意留有开口，缩小后容易被误认为渲染丢线。
- 页面缩放、非整数 DPI 和截图二次缩放会继续放大上述差异。

## 2. 当前结论

小尺寸图标使用下面的固定策略：

1. 统一图标槽位，当前工具导航为 `16×16px`。
2. 比较实际可见图形包围盒，不比较 SVG 文件尺寸或 CSS `font-size` 数字。
3. 优先选择为 `16px` 小尺寸设计的图标；`32px` 素材只有在关键坐标能整除为 `16px` 网格时优先使用。
4. 高频小图标优先使用实心、闭合轮廓或至少 `2px` 的稳定笔画。
5. 不因为图标库已有某个语义就强行使用；如果它缩小后不清晰，应换素材或制作小尺寸专用 SVG。

工具导航当前事实：

- `AI 服务配置`：复用 `icons/ss-switch-icons/extracted/claude.svg` 的原始路径，复制到前端受控资源目录后改为纯白品牌图标。
- `AI 字幕翻译`：`32×32` 字幕素材缩放为 `16×16`，通过 CSS mask 继承主题颜色。
- `资源捕获处理`：自制 `16×16` 实心抓手 SVG，表达“捕获到资源”，四根手指和掌部关键边界使用整数坐标。
- `媒体文件处理`：`32×32` 实心视频素材缩放为 `16×16`。
- 工具排序手柄：使用 `2×3` 的 CSS 点阵，每个点为 `2×2px`，位置使用整数像素；不再缩放 Semi UI 的 `24×24` 圆点路径。

## 3. 选图优先级

新增或替换图标时按下面顺序选择：

1. `src/assets/icons/material/` 中已经验证过的小尺寸素材。
2. 当前 UI 图标库中在目标尺寸下清晰、语义准确的图标。
3. workspace 根目录 `icons/` 中语义准确且网格合适的素材，确认后复制到前端受控素材目录。
4. 自行制作目标尺寸专用 SVG。

禁止仅因为“库里有一个名字接近的图标”就跳过视觉检查。品牌图标也不能拿来代表通用 AI 服务，除非该入口确实绑定对应品牌。

## 4. 自制 SVG 规则

现有素材都不合适时，可以自行制作 SVG。它不是临时补丁，而应作为受控的项目资产遵守以下规则。

### 4.1 画布与坐标

- 优先直接使用 `viewBox="0 0 16 16"` 设计最终小图标。
- 需要兼容现有 Material 素材时可使用 `32×32`，但缩到 `16px` 后的关键边界应尽量落在整数坐标。
- 实心矩形、闭合边界和关键对齐线使用整数坐标。
- `stroke-width="2"` 时让路径中心落在整数坐标，使两侧边界也落在整数坐标。
- `stroke-width="1"` 时路径中心应落在半像素坐标；高频导航图标通常不建议使用这么细的笔画。

### 4.2 视觉包围盒

- `16×16` 槽位中的主体通常占用约 `12px～14px`，四周保留稳定呼吸空间。
- 不要求所有图标的数学面积相等，但同组图标的视觉重量必须接近。
- 横向图标可以稍宽、纵向图标可以稍高，不通过整体缩小来迁就最长边。
- 复杂细节在 `16px` 下无法稳定辨认时应直接删除，不保留装饰性噪声。

### 4.3 造型与笔画

- 优先实心或闭合造型。
- 避免密集虚线、连续小圆点、短曲线和多个小于 `2px` 的间隙。
- 开口属于必要语义时必须在 `16px` 实际效果下确认不会被看成断线。
- 圆角半径、线宽和内部间距尽量使用整数值。

### 4.4 颜色与主题

- 通用 UI 图标默认跟随 `currentColor`。
- 外部 SVG URL 使用 CSS `mask-image` 加 `background: currentColor`，避免为亮暗主题维护两份颜色。
- 只有文件类型、品牌或状态本身依赖颜色时才保留 SVG 内置色值。
- 不用降低整体 `opacity` 制造次级状态；细线图标降低透明度后更容易发虚，应优先调整主题文字色。

## 5. 字标规则

`AI`、文件扩展名等文字型图标不能直接用与 SVG 相同的数字比较大小。

- 固定跨平台字体，不依赖 `-apple-system` 与 `Segoe UI` 自动切换。
- 按字体 cap height 校准大写字母的实际高度。
- 字标仍放入与其他图标一致的固定槽位。
- 如果字体在目标尺寸下仍不稳定，应把最终字形转为 SVG path，作为普通矢量资产管理。
- 字标不得用模糊的 `transform: scale()` 做长期校准。

## 6. 实现规则

图标尺寸只由稳定槽位控制：

```text
图标槽位：16×16px
按钮热区：单独定义，不随图标缩小
外部 SVG：mask-size 16×16px
```

不要同时在组件属性、SVG 文件和多处 CSS 中分别声明互相冲突的最终尺寸。图标需要特殊视觉校准时，只在图标类型 class 上调整，不改变整组槽位。

禁止对静止状态图标使用非整数 `translate`、`scale` 或父元素缩放。拖拽动画允许临时 transform，但落位后必须回到未变换状态。

## 7. 验证清单

每次新增或替换小图标至少检查：

- 在真实 `16px` 尺寸下查看，不只看 SVG 编辑器的大图。
- 与同组前后至少两枚图标并排比较可见面积和视觉重量。
- 亮色与暗色主题均无灰边、断线或颜色丢失。
- 页面缩放为 `100%`。
- macOS Retina 下清晰。
- Windows 100%、125%、150% DPI 下没有明显断边或尺寸漂移。
- active、hover、disabled 状态没有因透明度和颜色变化重新发虚。
- 截图用于交流时确认没有经过聊天工具的二次有损缩放；最终判断以应用真实界面为准。

## 8. 维护规则

- 同一组导航图标继续出现两次以上清晰度问题时，优先整体审计素材网格，不再逐个加 CSS 放大倍率。
- 新增自制 SVG 时记录它的目标展示尺寸和网格，不把只适合大尺寸的资产复用到高频小图标。
- 工具导航槽位或应用页面缩放基线变化时，必须重新验证本文列出的现有四枚图标。
