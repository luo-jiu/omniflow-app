# 本机会话组、归档与权限

更新时间：2026-10-21

## 当前结论

采用纯客户端方案。Electron main 和本机 SQLite 持有组、会话归属、归档及权限事实，按 backend/account/library 隔离。没有 Go 端表、云端同步或跨设备迁移接口；更换设备不会自动获得这些记录。Renderer 仅保存查询投影和交互状态，localStorage 只保存组折叠、上次打开会话等设备显示偏好。

## 会话组织

- 会话组只有一层，一个会话最多属于一个组；未分组用空 groupId 表示。组与真实资料库目录是不同对象，创建或删除组不会创建或删除文件。
- 右侧目录宽300px、固定高480px，只有当前位置的窗口可用高度不足时缩小；分组展开、折叠、空态及加载不改变面板高度，列表内部滚动。面板和聊天输入框圆角均为20px。保留12px停靠、374ms同步开合、440ms拖动回位。收起阈值1246px，聊天最大850px、最小640px以及左侧索引留白不变。
- 组展开后独立分页；统计来自Store聚合。侧边目录每组（含未分组）先展示5条，点击“展开更多”每次再展示5条，全部显示后隐藏按钮，收起该组时重置为5条。优先使用已经加载的查询投影，不够时才请求下一页；显示数量仅属局部UI状态，不改变管理页分页或组内总数。首次进入某个本机账号/后端/资料库组合时默认展开未分组和当前组，其他组按需展开；用户之后的展开/收起状态写入该设备的localStorage，重新进入时恢复上次状态，已保存的状态优先于当前会话自动展开。当前会话行仅显示标题，归档图标在hover/focus出现并预留位置。
- 组头用细线关闭/打开文件夹图标表示折叠状态，可新建该组会话、编辑名称。历史图标从顶部标题移到下方会话管理按钮前；其后为带图标的新建会话、归档、长期记忆图标。新建先选择组，首次发送才落Session；管理页支持搜索、组筛选及移动会话。
- 底部按钮的悬停背景统一使用胶囊圆角（999px），两端为圆头；等宽高的长期记忆按钮自然呈圆形。按钮尺寸、间距与悬停底色保持原值。
- “展开更多”新增行使用220ms的grid高度展开与淡入，不重新播放已有行；数据续页返回时同样生效。分组收起期间保留行，下次打开才重置为5条，避免收起动画被提前裁短。外层480px高度及底栏固定，减少动态效果偏好下关闭行动画。
- 删除组会将活动与归档会话移到未分组，显式完全访问保持不变。组名最多48字符，单库最多100组。

## 归档

归档不改变组归属，也不删除正文、工具记录和附件。活动列表排除归档，归档页支持搜索、组筛选、只读查看、恢复与确认后的永久删除。恢复优先回原组，组被删除后回未分组。永久删除只允许已归档会话；已发布到资料库的文件和独立长期记忆不随会话删除。

归档当前会话后选择同组最近的活动会话，没有则显示该组空态。当前输入有未发送草稿或附件时拒绝归档，避免丢失内容。运行、启动、等待审批/输入及停止收尾期间，不允许归档、移动或撤销所属组策略。main检查在途锁，SQLite另用trigger保护规范运行状态；同组内修改会话权限不受运行锁限制，只更新后续 Run 的设置。

## 会话权限

权限只有“询问访问 / 完全访问”两档。有无会话组均默认询问访问；组仅组织聊天，编辑器只提供组名、保存和原删除入口，不再提供目录自动授权配置。

| 会话模式 | 行为 |
| --- | --- |
| 询问访问 | 读取未授权文件先询问，写入沿用按次确认 |
| 完全访问 | 用户针对会话显式选择，沿用可信内置工具自动授权及原有硬性拒绝 |

权限可在任务运行、等待审批或等待回答期间切换，保存成功后由 main 会话元数据回填选择器。下一次发送或继续创建的新 Run 使用新设置；当前 Run 的目录、Shell 与电脑操作权限及待决审批继续使用原快照。保存不暂停任务、不处理现有审批，也不关闭本轮第一方电脑控件。首次创建/恢复元数据、保存权限及组织变更期间暂禁用选择器。菜单只显示两项，不增加说明或确认弹框。

旧 Session 中的 `group` 编码在规范会话读取和下一 Run 启动时统一按 `ask` 解释；不批量改写旧记录，不删除原组目录元数据。旧组重命名仍原样保留这些字段，新组使用空目录及 read。历史 Run 的 `library_access_json`、已构造的活跃 Run 快照和审批事实保持原值，不能将历史自动授权重写成询问。

每次 Run 冻结 libraryAccess 并进入能力 identity 和 SQLite 审计，之后不能改写。继续任务重新读取当前会话设置，不复用上一 Run 临时批准。Shell 内部保留原 `ask / auto / full-access` 策略类型，会话只映射 `ask / full-access`，不新增用户可选模式。

main在工具准入、元数据返回、正文读取、文件桥及renderer提交前执行检查；媒体上传在complete提交前再验证。初始感知只包含允许目录和选中节点，执行后重建受限感知；不直接信任renderer传回的整库快照。用于权限解析的内部元数据查询不作为模型可见结果，也不在批准前启动源存储探测。

缺少授权时使用内部control ToolRun `agent.access.request` 复用既有审批UI。普通读批准仅在本Run内复用，目录读批准包含后代；写批准绑定当次操作与目录身份。未知操作需要单次明确批准，不因名称具有某个前缀而自动放行。主进程仍保留原有schema、prepared action、一次性执行能力及提交结果校验。这里是应用级访问控制，不能保证远端目录变更与本机检查之间具有服务端事务原子性。

## 持久化与IPC

- `agent_session_groups`：owner/library、名称、根目录JSON、读写策略、元数据revision和policy_revision。
- `agent_sessions`：新增group_id、permission_mode及metadata_revision，复用archived_at。旧会话进入未分组/询问模式，已有当前baseline历史不清空。
- `agent_runs.library_access_json`：每次运行不可变的权限审计。沿用schema版本2的幂等补列，初始化不迁移其他服务数据。
- 新增 `agent:group:list/save/delete`、`agent:session:organize/archive`；list支持groupId/archived过滤，get显式includeArchived仅用于读取。
- `agent:tool:access-check` 绑定window/owner/library/session/run/execution，并在活跃执行的主进程回调内重新验证。Renderer不能提供额外授权目标。
