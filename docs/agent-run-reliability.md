# Agent 运行恢复与完成核对

更新时间：2026-09-09

## 网络恢复

- Provider 识别 Electron 普通 Error 中明确的 Chromium 瞬态连接错误（closed/reset/aborted/timeout/network changed/empty response/HTTP2 protocol），以及常见 Node 连接错误码。HTTP 错误仍按原结构化策略处理，不把认证、证书或未知应用错误当作瞬态网络错误。
- 尚未展示文字时，每次 Provider 请求最多额外重试2次，默认间隔500ms、1000ms，支持用户取消；重试相同模型请求，不执行或重放工具。main 通过既有 Run currentStep 显示“正在重新连接 n/2”，renderer 不自己计数。
- 已展示部分文字后，Provider 层不原样重试。Orchestrator 仅在本 Run 尚未尝试任何非只读工具、用户未取消、且出现已识别的流中断时，允许最多2次新的续接轮次。部分文字以带明确中断说明的 commentary 收口，不是最终答案；未完成的工具参数丢弃，已成功工具结果保留。权限快照与参数校验不变。
- 非只读工具一旦尝试（包括执行结果未知或失败），不启用上述部分响应自动续接，避免重放副作用。计划控制工具不属于外部副作用；未知工具按非只读处理。
- 当前 Run 语义摘要是无可见增量、无工具执行的缓冲请求；同类瞬态网络错误可额外重试2次。JSON/语义校验失败不因此重复请求；最终失败继续原子回滚，不提交半份摘要。

这不是网络稳定性保证。上游一直不可用时最终仍会停止；失败请求的用量也不包含在现有累计成功 usage 中。

## 长任务完成核对

- 至少8次成功工具调用且尚未尝试任何非只读工具时，模型第一次返回无工具的候选结尾会先作为 commentary 收口，在同一 Run 插入一次 main 生成的完成核对提示，再由模型判断继续必要步骤或给最终回答。写入、外部或未知工具一旦尝试，不追加这种自动核对续跑，避免引导重复副作用。
- 核对提示强调原任务范围、实际工具结果、读取覆盖与真实阻塞；不得把历史连接失败或模型自述当作当前中断。它不增加权限、不重放工具，也不创建可编辑计划或新的用户消息记录。
- 每个 Run 最多一次核对，短任务不额外请求。核对仍经过原预算/压缩/取消链路。代价是长任务可能多一次模型请求，已经正确的候选结尾也可能与最后回答重复展示。
- 该规则不是确定性任务完成证明；模型仍可能判断错误或报告真实阻塞。不能将 Run completed 等同于用户目标必然全部达成，验收仍需检查实际输出。
