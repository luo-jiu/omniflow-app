# Agent 运行恢复与完成核对

更新时间：2026-09-09

## 网络恢复

- Provider 识别 Electron 普通 Error 中明确的 Chromium 瞬态连接错误（closed/reset/aborted/timeout/network changed/empty response/HTTP2 protocol），以及常见 Node 连接错误码。HTTP 错误仍按原结构化策略处理，不把认证、证书或未知应用错误当作瞬态网络错误。
- 尚未展示文字时，每次 Provider 请求最多额外重试5次；按约5、10、20、40、60秒指数退避，带上下10%的抖动且单次最长60秒。HTTP响应支持秒数或日期形式的 Retry-After，在同一60秒上限内不早于服务端建议重试。等待可立即取消；重试相同模型请求，不执行或重放工具。main 通过既有 Run currentStep 显示“正在重新连接 n/5”，renderer 不自己计数。
- 已展示部分文字后，Provider 层不原样重试。Orchestrator 仅在本 Run 尚未尝试任何非只读工具、用户未取消、且出现已识别的流中断时，允许最多2次新的续接轮次，分别按约5、10秒退避并显示对应 n/2。部分文字以带明确中断说明的 commentary 收口，不是最终答案；未完成的工具参数丢弃，已成功工具结果保留。权限快照与参数校验不变。
- 非只读工具一旦尝试（包括执行结果未知或失败），不启用上述部分响应自动续接，避免重放副作用。计划控制工具不属于外部副作用；未知工具按非只读处理。
- 当前 Run 语义摘要是无可见增量、无工具执行的缓冲请求；同类瞬态网络错误可额外重试5次，并使用同一长退避与重连状态回调。该摘要客户端仍只对传输错误重试，不从普通错误文字推断HTTP状态或Retry-After。JSON/语义校验失败不因此重复请求；最终失败继续原子回滚，不提交半份摘要。

这不是网络稳定性保证。上游一直不可用时最终仍会停止；失败请求的用量也不包含在现有累计成功 usage 中。

## 主动停止后的继续

- 本机会话组启用后，继续会重新加载当前组的policyRevision和目录ID授权，冻结为新的libraryAccess；旧Run临时读授权和单次写批准全部失效。归档会话只能查看，恢复后才允许继续。组策略、会话权限和归档状态在启动及停止收尾阶段不能修改，避免新旧策略混用；详见 [本机会话组与访问](agent-session-groups-and-access.md)。

- 用户停止仍将原Run和未完成ToolRun收口为cancelled，原终态不能回退成running。输入区无新草稿/附件且会话最后一轮为cancelled时，发送位置显示细线播放图标；点击通过现有`agent:chat:start`传入`sessionId + resumeRunId`，不另建Session，也不新增可见提问。有新草稿或附件时恢复普通发送，表示新的提问。
- main只接受当前owner/资料库中最后一个cancelled Run；继续请求不能同时带新文本或新附件。上一轮由用户主动停止且仍在收尾时，继续或发送新提问都先等待其执行Promise结束，等待请求仍受startingRuns、owner释放和shutdown管理；owner释放触发的取消不能进入该等待通道，后到的stop调用不能改变取消来源。重复点击由会话启动锁及数据库的最新Run校验拒绝。
- 继续创建新的Run并保存不可变的`resumes_run_id`，继承原始目标和原附件引用，重新获取当前模型、权限、能力与工作区。SQLite原地补齐可空列及续接校验trigger，schema仍为2，不清除历史；跨Session、非cancelled来源、旧来源、修改目标和修改已保存续接关系均拒绝。旧Run和已完成ToolRun保持原样。
- Provider使用现有有界历史、独立Tool执行事实和新的继续指令。已完成/已提交操作不由main重放，取消时结果未知的写入必须先查询核对，再由模型决定剩余步骤。原Shell进程、临时Run工作区和准备能力已释放，不能把继续描述成原进程从指令位置恢复；需要重新感知或准备时沿用正常权限/确认流程。继续指令只附带工具名、状态和ok审计摘要，具体结果继续走原安全投影与上下文预算。
- 每次续接保留独立执行审计和对应user目标记录；renderer只根据规范resumesRunId串联，在原提问下展示同一逻辑任务，不按“继续”等文案猜测关系。不新增索引节点，最终完成时各次过程一起折叠；总用时累计执行段，排除两次启动之间的暂停时间。
- 主动停止的最后一个节点为黄色。接受继续或提交下一条新提问后清除该暂停色；failed/interrupted终态才为红色。该状态投影不改变规范Run status，取消不被伪装成失败。

## 长任务完成核对

- 至少8次成功工具调用且尚未尝试任何非只读工具时，接下来的待分类 Provider turn 在主进程有界缓冲；模型第一次返回无工具的候选结尾只进入本 Run 模型上下文，不发送正文 delta、不写入会话正文。对应空展示 item 正常收口并由既有规则隐藏，然后插入一次 main 完成核对提示。写入、外部或未知工具一旦尝试，不追加这种自动核对续跑。
- 核对提示强调原任务范围、实际工具结果、读取覆盖与真实阻塞；不得把历史连接失败或模型自述当作当前中断。它不增加权限、不重放工具，也不创建可编辑计划或新的用户消息记录。
- 核对期间只投影“正在核对结果”，核对轮次也缓冲到完整返回。若返回必要工具调用，正常展示过程说明并继续；若返回最终答案，只发布该答案。缓冲内容仍计入输出与运行字符预算，失败/取消不释放候选正文；不可见的部分响应允许安全重试，已经显示的文字仍禁止原样重放。
- 每个 Run 最多一次核对，短任务不额外请求。核对仍经过原预算/压缩/取消链路。代价是长任务可能多一次模型请求，且达到核对门槛后的部分过程说明要等 Provider turn 完成才显示；不再用重复显示候选答案来承担这个检查。
- 新行为适用于新Run。旧版本的候选正文与普通commentary没有独立标记，不根据文字猜测并删除既有历史记录。
- 该规则不是确定性任务完成证明；模型仍可能判断错误或报告真实阻塞。不能将 Run completed 等同于用户目标必然全部达成，验收仍需检查实际输出。
