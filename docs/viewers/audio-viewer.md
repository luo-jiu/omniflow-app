# 音频 Viewer

更新时间：2026-09-30
适用范围：裸音频文件、普通音乐文件夹、音频归档、全局音量偏好、共享音量控件和实时频谱。

## 1. 当前结构

裸音频、普通 `AUDIO + archiveMode=0` 文件夹和音频归档共用 `features/audio-viewer/components/unified-audio-viewer/` 的展开播放器。三种入口共用浮动控制台、轨迹进度条和进度动画，裸音频仍保留前后跳转语义；旧 `file-viewer/components/audio-viewer/`、`audio-waveform/` 以及只为旧播放列表跳转保留的 audio tab 上下文字段已经删除，不再维护第二套音频 UI。

三种入口只在数据来源和控制语义上不同：

- 裸 `.mp3/.flac/.m4a` 等文件直接使用当前文件 URL 和完整文件名，不扫描同级资源，不提供封面或歌词，不自动播放；封面位置保持空白，歌词显示“暂无歌词”，左右按钮表示后退 / 前进 10 秒。
- 普通音乐文件夹读取直属第一个音频、第一张图片和歌词候选，默认进入展开页并加载歌词，但不自动播放。
- 音频归档先展示歌曲列表，用户选择歌曲后可以进入同一展开页；左右按钮表示上一首 / 下一首，并提供列表循环模式。

展开页以浮动控制台中央播放键为虚拟分栏轴，不绘制分隔线。音频 viewer 容器宽于 `760px` 时使用左右等宽列：封面靠近左列内缘，歌词靠近右列内缘，二者在中轴两侧对称留白，间距随容器宽度保持 `64px～112px`；侧栏宽度变化不改变这条分栏轴。宽容器下封面整体向下偏移 `25px`，滚动后的高亮歌词以封面的实际中心为水平参考。右侧内容以整个应用窗口高度约 `1/4` 为基线，标题、歌词文件名和歌词舞台作为一个整体向上偏移 `25px`，内部间距与歌词舞台尺寸保持原样，通过 `use-audio-expanded-layout.ts` 测量 viewer 的窗口顶部偏移，扣除实际工具栏和标签栏占用；展开 / 返回 tab、容器尺寸变化和窗口缩放时更新，并在隐藏 / 收起 / 卸载时释放监听。窗口过矮时以标题区域的内容区顶部留白为下限。歌词在名称与文件名下面展开，底部仍避让频谱和控制台。标题按容器宽度使用 `28px～36px`，过长名称和歌词文件名省略，长歌词与无空格文本允许换行。歌词区填满内容行的剩余高度，频谱行收为 `64px～96px`，底部仍避让浮动控制台；歌词从顶部依次排列，高亮先向下移动；当前句中心到达封面中心对应的高度后，只滚动歌词舞台并让后续高亮保持在同一水平线上，该位置比舞台中线略高。滚动 presenter 仅在切句与尺寸变化时读取当前展开页中的封面和舞台几何，锚点限制在舞台可见范围内，不逐帧扫描 DOM。开头取消半屏留白和顶部渐隐，滚动后启用上下渐隐；底部留白按舞台高度减去锚点位置计算，让末句也能到达锚点。播放器、封面、舞台或高亮行尺寸变化会重新测量，回到开头与更换歌词能恢复顶部位置。容器不宽于 `760px` 时改为上下排列，取消封面向下及右侧区域向上的整体偏移以保持间距，滚动锚点回到歌词舞台中线；歌词舞台保留 `280px～600px` 的响应式高度，外层允许滚动。

实际出声和播放状态继续由 `globalAudioPlayer` 的单例 `<audio>` 拥有。裸音频、普通音乐文件夹、音频归档和 ASMR 都通过 `useGlobalAudioPlayback` 订阅同一播放状态并复用 `MediaVolumeControl`，组件不得创建第二个可播放音频实例，也不得绕过服务层注册 MediaHub。viewer 判断当前播放源时必须同时校验 `ownerType + ownerKey + tabId + libraryId`，不能只比较临时 URL；`sourceNodeId` 用于同一 owner 重建后恢复歌曲投影。

统一 viewer 负责三种入口的页面编排。直属资源发现收敛在 `audio-viewer-content.ts`，封面、歌词滚动和时间格式化等纯展示逻辑收敛在 `audio-viewer-presenters.tsx`，异步链接解析与组件侧请求清理收敛在 `use-audio-card-playback.ts`；裸音频遵守 `audio` 的 `warm: none` policy，不注册归档 snapshot adapter。

歌词候选和读取由 `use-audio-card-subtitles.ts` 与共享 `useTimedText` 拥有，独立于播放请求。归档当前展示歌曲（当前播放歌曲、选中歌曲或首张卡片）确定后，只读取该歌曲文件夹的直属歌词候选；普通音乐文件夹复用首次目录发现的候选，不重复扫描；裸音频与历史直属媒体卡片不扫描伴随文件。歌词重置以资料库、入口资源、歌曲节点与内容 / reload 版本为 key，开始播放或签名音频 URL 改变不会重新清空 / 请求同一首歌词；切歌、换库和卸载后的旧目录结果不得写回，新歌无歌词时清除旧歌文本。读取歌词不请求音频播放链接、不接管全局播放器，也不创建播放实体；播放流程只处理音频源与出声。

播放请求的最终仲裁由 `globalAudioPlayer` 持有，而不是由某个 viewer 私有持有。普通音频、音频归档、普通音乐文件夹和 ASMR 在请求临时链接前取得同一全局 generation token，只有 token 仍为最新时才能执行 `ensureSource` 和提交 `play`。旧 viewer 卸载时只允许取消自己仍为最新的请求，不得使另一个 viewer 已发起的新请求失效；暂停、关闭 tab、切换资料库或新的直接播放操作都会让旧 token 失效。

## 2. 音量偏好

音量偏好的唯一 owner 是 `media-volume-preference.ts`：

- 本机持久化 key：`omniflow:media-volume-preference:v1`
- 保存 `volume`、`muted` 和 `lastAudibleVolume`
- 拖动任意音频播放器的音量后，其他音频播放器立即读取同一结果
- 应用重启后恢复上次音量和静音状态
- 音量拖到 `0` 时进入静音；解除静音时恢复最后一次非零音量
- 偏好只保存在当前设备，不进入账号偏好、Viewer Session 或后端

`globalAudioPlayer.setVolume` 和 `setMuted` 只能写入该 preference，再由 preference 投影到单例 `<audio>`。viewer 不得自己增加持久化 key 或局部音量 state。

## 3. 实时频谱

统一展开播放器复用 `globalAudioPlayer` 内唯一的 Web Audio `AnalyserNode`，canvas 每帧直接读取当前正在出声的 FFT 频率桶。分析输入来自单例 `<audio>` 解码后的 `captureStream()` 音轨，因此不按 MP3、M4A、FLAC 等扩展名分别实现：只要 Chromium 能正常播放且能暴露解码音轨，就使用同一条真实频谱链。对象存储链接通常与 renderer 不同源，单例 `<audio>` 必须在设置 `src` 前启用 `crossOrigin = 'anonymous'`，存储节点也必须允许当前 renderer origin；否则普通播放仍可能成功，但捕获音轨会因跨域保护只输出静音。部分容器会在 `play()` 之后延迟加入音轨，服务层必须同时监听 `addtrack` 并做有上限的短期重试；每次切换播放源都要释放旧 `MediaStreamAudioSourceNode` 和 `AudioContext`，再为新源重建分析图，不能让新歌曲继续读取上一首已经结束的音轨。

频谱不下载第二份音频、不把完整文件以 base64 送入 renderer，也不做整曲 PCM 解码或后台预计算；换歌、暂停和切走 tab 后不存在遗留分析任务。分析节点尚未就绪、宿主无法捕获音轨或真实频率桶为零时，柱体必须平滑回落至零，不生成与声音无关的模拟动画，避免把兜底动效误判为格式已支持。每帧将 `45Hz～16kHz` 以对数频带映射成一条占画布 `80%` 的浅色原波，覆盖 `0%～80%`；同一组高度逐柱倒序镜像后形成同色系深色镜像波，覆盖 `20%～100%`，两层组合后的外轮廓保持中心对称。解码后的 FFT 强值必须再经过非线性柱高曲线，满幅输入的柱高不超过画布约 `26%`、中等输入约为画布 `10%`，避免响度较高的正常歌曲占满频谱区域。深色镜像层先绘制、浅色原波位于前层。

存在歌曲封面时，两档颜色从过滤透明、近黑、近白及低饱和像素后的封面主色相衍生；裸音频没有封面，始终回退当前主题强调色的一浅一深搭配。两层共用同一组目标高度和时间平滑结果，并统一应用边缘透明度渐变和首尾归零高度包络，不得重新采样第二组频段或套用固定山峰模板。暂停时低于一个物理像素后钳为零并彻底清空；收起播放器或切走当前 tab 后停止逐帧刷新。

频谱与底部进度条共用 `useAudioSpectrumColors` 的唯一配色结果。无封面、近灰封面和取色失败时，默认前层读取AppearanceViewContext目标快照的accent.default，镜像层按同色与黑色65:35混合，进度沿同一深浅配色渐变。配色切换、自定义强调色、主题预览/取消即使明暗模式不变也立即更新，Canvas不读取动画中的computed CSS。封面取色只在封面URL或明暗变化时重新请求，旧请求取消后不覆盖当前默认色。裸音频、普通 `AUDIO` 文件夹与音频归档共用圆角浮动控制台和 SVG 轨迹进度条，展开页的频谱与控制台保持较小且稳定的垂直间距，并在窄窗口下同步收缩；轨迹进度条内部使用透明 range 作为点击、拖拽和键盘交互层，拖动或按键调整期间只更新本地位置和时间预览，释放后才提交一次 seek。视觉层不显示圆点 thumb，已播放区域从 `00:00` 一侧的深色渐变到当前位置的浅色；三种入口自动循环重播时都触发同一进度动画。

## 4. 控制栏语义

- 音频归档列表模式下，左右按钮表示上一首 / 下一首
- 裸音频模式下，左右按钮表示后退 / 前进 10 秒，不显示循环模式按钮
- 音频归档气泡中央播放/暂停按钮常态、悬停、按下和聚焦均用主题强调色，切换仅更换图标；背景保留原交互反馈，禁用时仍用禁用色。
- 没有行为的装饰按钮不得显示
- 播放、上一首、下一首、快退、快进和音量按钮必须提供 title 与 aria-label

## 5. 验证

至少验证：

1. 裸音频、普通音乐文件夹、音频归档和 ASMR 任一处调整音量，其他入口显示一致。
2. 重启应用后音量、静音和解除静音恢复值正确。
3. 裸音频默认进入展开页，名称为完整文件名，封面区域为空，歌词显示“暂无歌词”，进入时不自动播放。
4. 裸音频左右按钮按 10 秒跳转，且不显示循环按钮；文件夹和归档仍保持各自列表语义。
5. 亮色、暗色主题下频谱、音量轨道、焦点态和禁用态均可辨认。
6. 进度条点击、拖拽和键盘 seek 的时间显示与实际播放一致。
7. 播放时频谱随声音跳动，暂停后平滑回落；收起、调整窗口宽度、切 tab、切歌后没有残留动画、旧柱高度或第二路声音。频谱宽度不得超过底部控制台，控制台与频谱在窄窗口下同步收缩；三种入口自动循环重播时，控制台进度动画仍会触发。
8. 有彩色封面时频谱和进度条保持同一封面主色相的一浅一深搭配；裸音频、无封面和取色失败时回退主题强调色。
9. 在两个音频 tab 或 ASMR 与普通音频之间快速交替点击时，只有最后一次操作可以接管全局播放器；较慢的旧链接请求完成后不得改歌、出声或弹错。
10. MP3、M4A、FLAC、AAC、OGG、OPUS 和 WAV 等实际可播放样本均只显示真实频谱；切换不同格式后新歌曲不能沿用旧音轨，分析不可用时频谱归零且音乐继续播放。
11. 首次进入普通音乐文件夹或从音频归档展开当前歌曲，不按播放键也应显示库内 LRC / QRC XML 歌词；开始播放不闪退为“暂无歌词”。快速换歌、换库、切到无歌词歌曲和关闭 tab 后不出现旧歌词。
12. 三种入口的展开页在宽容器下均以播放键中心分成封面左列、歌词右列；检查 `800px / 760px / 440px / 320px` 容器、亮暗主题、长标题、长歌词、开头顶部排列、高亮到封面中心后跟随及末句水平对齐、窄布局中线跟随，不出现横向溢出。

## 6. 维护规则

修改音量状态 owner、持久化 key、频谱加载策略、音频入口模式或控制栏语义时，必须同步更新本文、`docs/media-hub-contract.md` 和 `docs/frontend-validation-matrix.md`。
